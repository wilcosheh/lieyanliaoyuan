# 烈焰燎原 · 玩法设计

本文是战斗规则的唯一细则：角色、技能、施法、打断、完成度、胜负和服务器裁决。

| 项                       | 内容                                                                   |
| ------------------------ | ---------------------------------------------------------------------- |
| 读者                     | 产品、策划、客户端、战斗服务器、测试                                   |
| 产品范围                 | 见 [设计文档](./设计文档.md)。功能、终端、账号、商业不在本文重复       |
| 玩家听到什么、灵矽怎么说 | 见 [交互设计](./交互设计.md)                                           |
| 怎么存、接口和拒绝码     | 见 [架构设计](./架构设计.md)。本文不规定部署、表和路径                 |
| 数值                     | 首版建议值。可以按对局数据调整数值，不改变阶段顺序，也不改变服务器权威 |

产品上的战斗是：双方同时念当前角色的技能。服务器先处理到的合法「施法完成」结算，并打断对方尚未完成的施法。已经进入结算的技能会完整生效。被打断的那一句不结算、不扣次数。下一回合两边仍可念。

对局按回合结算。每一回合只生效一个技能，回合结束再处理持续伤害和状态。回合里面双方同时念，施法时间就是把技能名念完的真实时间。玩家感受到的是实时对局，回合是结算单位。

## 1. 和产品文档的分工

功能范围、终端、账号、收费和学习在产品里的目的，以设计文档为准。本文规定这些功能进入对局之后怎么裁决。交互文案不改变本文的胜负和数值。

## 2. 学习判定

**目的：** 让玩家熟悉所选角色的 7 个技能名，并听清完成度如何改变直接伤害。

**流程：**

1. 选择角色。未购买的后续角色不可进入练习。
2. 查看该角色每个技能：标准技能名、基础或角色技能、使用规则、效果。伤害和持续伤害按完成度
   100 展示完整数值，并说明完成度会按比例降低这两类数值。
3. 跟读或自己念一句。
4. 立刻听到结果。念对时听到完成度和按该完成度算出的效果。没念对时听到失败提示。
5. 可继续练，或带着该角色进入对电脑或联机。

学习与对战共用同一套规则：转写文字必须与该角色某一个标准技能名完全一致；完成度只缩放直接伤害和持续伤害的基础伤害。练习不创建正式对局，不记录胜负，不消耗技能使用次数。

**反馈：** 判定与对战相同。玩家听到的原句以交互设计为准。

| 情况                                       | 结果                                 |
| ------------------------------------------ | ------------------------------------ |
| 与一个标准技能名完全一致                   | 按该完成度预览伤害、治疗、护盾或状态 |
| 一句话里同时含有该角色两个及以上标准技能名 | 不生效。听到「一次一道。」           |
| 对不上任何标准技能名                       | 不生效。听到「咒语没成。」           |

可选木桩：只用于把这一档伤害、治疗或护盾念出来。木桩不还手，不进入正式对战记录。

## 3. 角色与技能

**角色**是一套固定技能和打法。战前选择，本局锁定。本局只能念该角色配置中的标准技能名。

每个角色恰好 7 个技能：1 个基础技能，6 个角色技能。基础技能都是伤害型。

| 角色     | 标识        | 战斗定位       | 基础技能 | 主要策略                             |
| -------- | ----------- | -------------- | -------- | ------------------------------------ |
| 烈焰剑士 | `swordsman` | 进攻爆发       | 破风斩   | 快速突刺、进攻增益、破甲、斩杀       |
| 圣光守卫 | `guardian`  | 防守续航       | 守阵重击 | 护盾、减伤、治疗、净化               |
| 暗影术士 | `warlock`   | 增益循环       | 蚀魂弹   | 叠加进攻和防御增益，再释放复合技能   |
| 风行弓手 | `archer`    | 减益和特殊效果 | 疾风箭   | 持续伤害、降伤、破盾、驱散和行动限制 |

服务器按 `character_id` 读取角色和技能配置。客户端不能上传技能数值。

### 3.1 技能名称

- 同一角色的 7 个技能名必须唯一。其中 1 个标记为基础技能。
- 技能名不再统一长度。技能强度与念诵长度放在同一套平衡里。
- 基础技能建议 3–4 个汉字，中等技能建议 5–7 个汉字，终极技能建议 8–12 个汉字。
- 强力技能使用更长、更完整的名称，让对手有更多机会先念完短技能，并打断这段施法。
- 技能名不得包含同音字、同音词，或仅靠声调区分的变体。
- 同一角色的技能名和展示文本不得形成同音冲突。首版不配置别名。
- 技能名不应包含常见闲聊词，避免误触发。
- 首版不支持自定义快捷词。服务器只做标准技能名的完全匹配。

每个角色的 6 个角色技能建议包含 2 个快速小技能、3 个中型技能和 1
个长技能。行动限制、强力驱散和复合效果使用较长的标准名称，并通常每局一次。

`phrase_length_tier`
只用于内容设计。施法要花多久，就是玩家把这句技能名念完并送到服务器的时间。谁先完成，只看「施法完成」在战斗房间里被处理的顺序。

内容在发布前必须拒绝：同音字、同音词、同音别名、自定义快捷词。

### 3.2 使用规则

| 槽位     | 数量 | 默认规则                       | 标识                    | 设计目的           |
| -------- | ---: | ------------------------------ | ----------------------- | ------------------ |
| 基础技能 |    1 | 次数不限，但不能连续两回合使用 | `BASIC_NON_CONSECUTIVE` | 稳定的低收益行动   |
| 角色技能 |    6 | 默认每局成功使用 1 次          | `ONCE_PER_MATCH`        | 角色差异和技能组合 |

少量角色技能可以配置为 `LIMITED_REPEAT`，必须写明 `max_uses_per_match` 和
`min_round_gap`。除基础技能外，未特别配置的技能都是每局成功使用一次。能否重复由服务器配置决定。

```text
第 N 回合使用基础技能后，第 N+1 回合不可再用，第 N+2 回合可以再用。
```

可用性：

```text
skillUsable(state, skill, currentRound):
    usage = state.skill_usage[skill.skill_id]
    lastRound = state.skill_last_used_round[skill.skill_id]

    if skill.reuse_rule == ONCE_PER_MATCH:
        return usage == 0
    if skill.reuse_rule == BASIC_NON_CONSECUTIVE:
        return lastRound == null or currentRound - lastRound >= 2
    if skill.reuse_rule == LIMITED_REPEAT:
        return usage < skill.max_uses_per_match
            and (lastRound == null or currentRound - lastRound >= skill.min_round_gap)
```

只有施法完成、通过校验并进入结算的使用才增加次数、写入最近使用回合。识别失败、念到一半取消、被打断、次数不足、间隔不足、行动受限，都不增加次数。

### 3.3 效果类别

一个技能可以包含多个效果。服务器按该技能配置的效果顺序结算。

| 效果类别     | 标识              | 目标       | 规则                                                     |
| ------------ | ----------------- | ---------- | -------------------------------------------------------- |
| 削减血量     | `DAMAGE`          | 对方       | 先扣对方护盾，再扣生命。受攻击增益和防御减益影响         |
| 回复自身血量 | `HEAL`            | 自身       | 不得超过生命上限。可配置立即治疗，或回合结束时的周期治疗 |
| 添加护盾     | `SHIELD`          | 自身       | 不得超过护盾上限                                         |
| 添加自身增益 | `SELF_BUFF`       | 自身       | 防御型或进攻型。按持续回合或触发次数消耗                 |
| 添加对方减益 | `OPPONENT_DEBUFF` | 对方       | 进攻型或防御型。可包含持续伤害、降低对方伤害             |
| 特殊效果     | `SPECIAL`         | 自身或对方 | 破盾、解除增益或减益、一回合行动限制                     |

增益和减益的方向：

- 防御型自身增益：持续回复、减少受到的伤害、提高护盾获得量。
- 进攻型自身增益：提高伤害、提高特定技能伤害、提高持续伤害。
- 进攻型对方减益：持续伤害、提高对方受到的伤害、降低对方治疗。
- 防御型对方减益：降低对方造成的伤害、降低对方护盾或治疗。

`SPECIAL` 在首版可以配置：

| 标识                   | 作用                                                       |
| ---------------------- | ---------------------------------------------------------- |
| `BREAK_SHIELD`         | 解除对方全部护盾，或削减配置中的护盾值                     |
| `REMOVE_OPPONENT_BUFF` | 解除对方一个、多个或指定标签的增益                         |
| `CLEANSE_SELF_DEBUFF`  | 解除自身一个、多个或指定标签的减益                         |
| `ACTION_RESTRICTION`   | 令对方下一次行动阶段无法行动。状态名可以是石化、麻痹或冻结 |

行动限制只影响下一回合能不能开始施法。它不会取消已经进入结算的技能，也不会改写已经产生的结果。对方尚未完成的施法，由先到达的「施法完成」打断，不靠行动限制。第
N 回合附加上的 1 回合行动限制，作用于第 N+1 回合。

控制状态：

1. 同一玩家同一时间只保留一个行动限制。
2. 重复施加时刷新持续时间，不叠加多层「无法行动」。
3. 新状态从下一回合开始计算。在被限制的那个回合的结束阶段扣减持续时间，归零后移除。
4. 驱散和净化只能移除配置允许移除的标签。

破盾、驱散或净化时，如果目标身上没有对应状态，记录 0
点效果。这一次行动仍然成功，不返还技能次数。

### 3.4 状态

所有持续效果使用同一种状态对象：

```text
StatusEffect
- effect_id
- effect_type         BUFF / DEBUFF / DOT / ACTION_RESTRICTION
- effect_tag          OFFENSE / DEFENSE / CONTROL / HEAL_OVER_TIME
- source_player_id
- source_skill_id
- value
- remaining_rounds
- remaining_triggers
- stack_count
- dispellable
- perfection          仅 DOT 保存施加当次的完成度
```

战斗阶段附加的状态，从下一回合开始计时。同一个回合的结束阶段不立刻扣减刚附加上的持续时间。

同类状态默认不无限叠加。重复施加时按技能配置选择「刷新持续时间」「取更高数值」或「增加层数」。未特别配置时，刷新持续时间并取更高数值。持续伤害也遵守该技能来源的最大层数，避免同一技能无限叠层。

### 3.5 配置

技能用效果数组表达。服务器根据 `skill_id` 和 `effect_version`
读取完整配置。下面是形式示例，不是首发角色的正式数值：

```json
{
  "skill_id": "flame_breaker",
  "slot_type": "CHARACTER",
  "name": "焚炎破阵诀",
  "cast_phrase": "焚炎破阵诀",
  "phrase_length_tier": "MEDIUM",
  "reuse_rule": "ONCE_PER_MATCH",
  "max_uses_per_match": 1,
  "min_round_gap": 0,
  "effects": [
    { "type": "DAMAGE", "target": "OPPONENT", "value": 120 },
    {
      "type": "OPPONENT_DEBUFF",
      "tag": "DOT",
      "value": 25,
      "duration_rounds": 2
    }
  ],
  "effect_version": 1
}
```

客户端提交的是开始施法、取消施法，或施法完成。灵矽只提交它已经转好的文字和完成度。Game
server
不把录音再识别一遍。基础伤害、治疗、护盾、持续时间、触发次数、驱散范围和行动限制都来自服务器配置。录音只用于对方收听。

### 3.6 数值区间

正式技能以第 3.7–3.10 节为准。新技能设计时落在下列区间：

| 效果方向           | 建议念法长度 | 默认使用规则               | 效果区间                                        |
| ------------------ | -----------: | -------------------------- | ----------------------------------------------- |
| 快速小技能         |         4 字 | 每局 1 次，或有限重复      | 60–90 伤害，或单一低数值效果                    |
| 基础技能           |       3–4 字 | 不限次数，但不能连续两回合 | 50–80 伤害                                      |
| 单次强力伤害       |       5–7 字 | 每局 1 次                  | 110–170 伤害                                    |
| 治疗或护盾         |       5–7 字 | 每局 1 次                  | 90–180 治疗，或 120–220 护盾                    |
| 自身增益           |       5–8 字 | 每局 1 次或 2 次           | 持续 2–3 回合，或 2–3 次触发                    |
| 对方减益、持续伤害 |       5–8 字 | 每局 1 次，或有限重复      | 持续 2–3 回合。单次收益不超过同档直接伤害       |
| 破盾、驱散         |       5–8 字 | 每局 1 次                  | 解除一个目标类别，或相当于 100%–200% 的基础护盾 |
| 行动限制           |      8–12 字 | 每局 1 次                  | 对方下一回合无法行动                            |

快速小技能仍然消耗本局使用次数，不能当成没有成本的普通攻击。

### 3.7 烈焰剑士

高伤害、连击和收割。用短技能先念完并打断对方，用短期进攻增益提高后续伤害。

| 技能             | 效果                        | 使用规则  | 念法长度 | 建议效果                                                                                 |
| ---------------- | --------------------------- | --------- | -------- | ---------------------------------------------------------------------------------------- |
| 破风斩           | `DAMAGE`                    | 基础技能  | 短，3 字 | 造成 65 伤害                                                                             |
| 锐刃突刺         | `DAMAGE`                    | 每局 1 次 | 短，4 字 | 造成 80 伤害                                                                             |
| 焰步追击         | `DAMAGE`                    | 每局 1 次 | 短，4 字 | 造成 75 伤害                                                                             |
| 裂甲连环斩       | `DAMAGE`、多段              | 每局 1 次 | 中，5 字 | 两段各 55 伤害，按完成度缩放。目标有护盾时，每段再削减 15 点护盾；这 15 点不按完成度缩放 |
| 战意燃锋诀       | `SELF_BUFF`，进攻           | 每局 1 次 | 中，5 字 | 2 回合内接下来 2 次攻击伤害提高 25%                                                      |
| 血刃追魂印       | `DAMAGE`、`OPPONENT_DEBUFF` | 每局 1 次 | 中，5 字 | 造成 90 伤害。目标 2 回合内受到伤害提高 15%                                              |
| 焚天裂空万刃归一 | `DAMAGE`                    | 每局 1 次 | 长，8 字 | 造成 260 伤害。不附加控制                                                                |

要先念完并打断对方时，用锐刃突刺或焰步追击。准备爆发时先用战意燃锋诀，再用裂甲连环斩和血刃追魂印。破风斩用来填补其他技能不可用的回合。焚天裂空万刃归一留给斩杀。裂甲连环斩的每一段，若该段开始时目标有护盾，先削减
15 点护盾，再结算该段伤害。

### 3.8 圣光守卫

护盾、减伤和治疗。输出低于烈焰剑士，用承受和回复拖长对局。

| 技能             | 效果                  | 使用规则                       | 念法长度 | 建议效果                                               |
| ---------------- | --------------------- | ------------------------------ | -------- | ------------------------------------------------------ |
| 守阵重击         | `DAMAGE`              | 基础技能                       | 短，4 字 | 造成 55 伤害                                           |
| 护阵回击         | `DAMAGE`、`SHIELD`    | 每局 1 次                      | 短，4 字 | 造成 65 伤害，并获得 40 点护盾                         |
| 安魂微光         | `HEAL`                | 每局最多 2 次，间隔至少 2 回合 | 短，4 字 | 恢复 65 生命                                           |
| 圣甲护身诀       | `SHIELD`、`SELF_BUFF` | 每局 1 次                      | 中，5 字 | 获得 210 点护盾，并在 2 回合内受到伤害降低 20%         |
| 回春守势诀       | `HEAL`、`SELF_BUFF`   | 每局 1 次                      | 中，5 字 | 立即恢复 100 生命。接下来 2 个回合结束时各恢复 45 生命 |
| 圣光净化万象咒   | `SPECIAL`             | 每局 1 次                      | 中，7 字 | 解除自身和对方的全部可驱散减益与增益                   |
| 神圣壁垒永昼长明 | `SHIELD`、`HEAL`      | 每局 1 次                      | 长，8 字 | 获得 280 点护盾，并恢复 120 生命。不附加行动限制       |

低风险行动用护阵回击或安魂微光。圣甲护身诀建立防守，回春守势诀负责续航。圣光净化万象咒用来处理对方的持续伤害、增伤或减伤。

### 3.9 暗影术士

自身直接伤害不高，靠进攻和防御增益提高后续技能的价值。增益不能靠重复施放无限叠加。

| 技能             | 效果                  | 使用规则                       | 念法长度 | 建议效果                                       |
| ---------------- | --------------------- | ------------------------------ | -------- | ---------------------------------------------- |
| 蚀魂弹           | `DAMAGE`              | 基础技能                       | 短，3 字 | 造成 60 伤害                                   |
| 咒火弹           | `DAMAGE`、`SELF_BUFF` | 每局 1 次                      | 短，3 字 | 造成 75 伤害。下一次技能的首个效果提高 10%     |
| 灵息聚能         | `SELF_BUFF`           | 每局最多 2 次，间隔至少 2 回合 | 短，4 字 | 1 回合内，下一次技能效果提高 15%               |
| 幽冥增幅契       | `SELF_BUFF`           | 每局 1 次                      | 中，5 字 | 3 回合内伤害提高 20%，且下一次治疗效果提高 30% |
| 血契回流式       | `HEAL`、`SELF_BUFF`   | 每局 1 次                      | 中，5 字 | 恢复 110 生命。2 回合内治疗效果提高 25%        |
| 虚空咒能聚合     | `SELF_BUFF`           | 每局 1 次                      | 中，6 字 | 2 回合内，下一次技能的第一个效果数值提高 35%   |
| 万咒归源幽冥禁章 | `DAMAGE`、`SELF_BUFF` | 每局 1 次                      | 长，8 字 | 造成 190 伤害。获得 2 回合伤害提高 20%         |

快速准备用咒火弹或灵息聚能，再用幽冥增幅契和虚空咒能聚合。血契回流式调整生命。万咒归源幽冥禁章用来兑现已经叠上的增益。

### 3.10 风行弓手

用持续伤害、降伤、破盾、驱散和一回合行动限制改变节奏。先念完的任何技能都能打断对方还在念的技能。行动限制另外拿走对方的下一回合，不取消已经进入结算的那一击。寒星封行九霄长矢本身字数长，可能在念完前被短技能打断。

| 技能             | 效果                           | 使用规则                       | 念法长度 | 建议效果                                  |
| ---------------- | ------------------------------ | ------------------------------ | -------- | ----------------------------------------- |
| 疾风箭           | `DAMAGE`                       | 基础技能                       | 短，3 字 | 造成 60 伤害                              |
| 裂风短矢         | `DAMAGE`                       | 每局 1 次                      | 短，4 字 | 造成 75 伤害                              |
| 穿甲短矢         | `DAMAGE`、`BREAK_SHIELD`       | 每局 1 次                      | 短，4 字 | 造成 65 伤害，并移除目标 40 点护盾        |
| 毒雨连射阵       | `OPPONENT_DEBUFF`、持续伤害    | 每局最多 2 次，间隔至少 2 回合 | 中，5 字 | 目标在接下来 3 个回合结束时各受到 35 伤害 |
| 蚀心削势矢       | `OPPONENT_DEBUFF`，防御        | 每局 1 次                      | 中，5 字 | 目标 2 回合内造成的伤害降低 25%           |
| 破界散射万象术   | `SPECIAL`                      | 每局 1 次                      | 中，7 字 | 移除目标全部可驱散增益，并削减 80 点护盾  |
| 寒星封行九霄长矢 | `DAMAGE`、`ACTION_RESTRICTION` | 每局 1 次                      | 长，8 字 | 造成 80 伤害。目标下一回合无法行动        |

补伤害或处理薄盾时用裂风短矢、穿甲短矢。毒雨连射阵制造持续压力，蚀心削势矢压低对方爆发。对方开增益时用破界散射万象术。寒星封行九霄长矢用来拿走下一回合。

## 4. 对局规则

本章是战斗流程的基准。数值和技能效果可以调整，阶段顺序和服务器权威不能改。

一回合里双方同时施法。服务器先处理到的那条合法「施法完成」结算，并打断对方还没完成的施法。已经进入结算的技能会完整生效，不能再被打断。同一回合只结算一个技能。

### 4.1 基础参数

| 参数       |                       首版值 | 说明                                             |
| ---------- | ---------------------------: | ------------------------------------------------ |
| 对战人数   |                       1 对 1 | 后续可扩展，首版不做 2 对 2                      |
| 对局模式   |                         单局 | 一次开局只打一局                                 |
| 单局时长   |                         不限 | 一直进行，直到生命、认输、离开或异常结束分出结果 |
| 单回合时长 |                         不限 | 停在等待施法，直到出现合法的施法完成或对局结束   |
| 初始生命   |                         1000 | 四名角色相同。生命上限 1000                      |
| 护盾上限   |                          500 | 超过部分不保留                                   |
| 开局护盾   |                            0 |                                                  |
| 每回合结算 |                     1 个技能 | 先被处理的合法施法完成                           |
| 打断       |         取消对方施法中的技能 | 被打断的技能不结算、不扣次数。不因此锁定下一回合 |
| 判定顺序   | 服务器处理「施法完成」的顺序 | 不采用客户端的开始时间、结束时间或语音时长       |
| 完成度     |                        0–100 | 省略时按 100。只缩放直接伤害和持续伤害           |

房间因断线或异常被回收，属于基础设施，不作为回合超时，也不作为「时间到判平」。

### 4.2 单回合的三个阶段

| 阶段     | 状态           | 主要工作                                           | 结束条件                                       |
| -------- | -------------- | -------------------------------------------------- | ---------------------------------------------- |
| 倒数     | `COUNTDOWN`    | 服务器发一句「三。二。一。」并计时。此间不接受施法 | 倒数结束                                       |
| 回合开始 | `WAITING_CAST` | 双方都可以开始施法、取消，或提交施法完成           | 第一条合法的施法完成进入结算，或双方都无法施法 |
| 战斗     | `SETTLING`     | 打断对方尚未完成的施法，并结算先到的技能           | 结果已持久化                                   |
| 回合结束 | `ENDING`       | 持续伤害、周期治疗、状态计时、死亡检查             | 进入倒数，或结束对局                           |

无效的开始、取消和完成不推进阶段。服务器一直停在
`WAITING_CAST`，直到收到合法的施法完成，或对局因终局、认输、离开、异常结束。

```text
倒数 COUNTDOWN
  → 服务器按同一时钟发 3、2、1
  → 此间的开始施法和施法完成不接受
  → 倒数结束：进入回合开始
回合开始 WAITING_CAST
  → 开始施法：记下施法中。施法被接受后，把这句录音播放给对方。不结算
  → 取消或识别失败：清除自己的施法中，停止转播。对方继续
  → 施法完成且合法：进入结算，停止转播
战斗 SETTLING
  → 若对方仍在施法中，打断对方，并停止其语音
  → 结算自己的技能
  → 已分出胜负：结束对局，不再做本回合的结束效果
回合结束 ENDING
  → 持续伤害和周期伤害
  → 周期治疗和其他回合结束回复
  → 更新已经在生效的增益、减益和行动限制的剩余回合
  → 移除到期效果
  → 再次检查死亡
  → 双方仍存活：战况播完后进入倒数
  → 有人生命 ≤ 0：结束对局
```

回合结束的这五步顺序固定，并写入测试。以后若某个新效果要插队，增加明确的优先级配置，不能靠代码碰巧的执行顺序。

### 4.3 回合开始

进入回合时：

1. 对局状态为 `RUNNING`，双方仍然存活。
2. 创建回合。首回合 `round_no = 1`，之后递增。
3. `round_status = WAITING_CAST`。双方的施法状态都是空闲，清空本回合结算者和技能。
4. 向双方发送
   `ROUND_STARTED`：回合号、双方战斗快照、当前角色可展示的技能。回合号只给终端对齐，不念出来。
5. 检查「本回合不可行动」。被石化、麻痹或冻结的一方本回合不能开始施法，另一方仍可施法。双方都被限制时，本回合没有技能行动，不消耗任何技能次数，直接进入回合结束。

开战和每一回合结束之后，都先进入
`COUNTDOWN`，不直接开放施法。服务器发一句「三。二。一。」，并按同一时钟决定倒数何时结束。终端只念服务器发出的这一句，不自己另数。倒数期间的开始施法和施法完成返回
`ROUND_NOT_OPEN`，不进入施法中。倒数结束才把该回合设为 `WAITING_CAST`。

战况先由终端播完。需要出声的一侧回执后，服务器才开始倒数。某一侧超过 5
秒没有回执，服务器不再等它。同机双人只有一只喇叭，一次回执即可。对电脑只等玩家这一侧。

对局中的一句，由灵矽完成转写。Game server
只收转写文字和完成度，不对录音再做识别，也不从录音重算完成度。

对方的原声只在 Web
的施法完成里已经带了可播放地址时，放在战况前面给对方。没带上不推迟战况和倒数。施法者自己不听回放。灵矽首版不播放对方原声，也不从聊天记录取地址。同机双人不播放。对电脑播放预先准备的技能语音。Web
不经过灵矽，由浏览器把自己的转写、完成度和录音地址交给 Game
server，服务器同样不转写。

服务器先看转写是不是对局口令：看血、还有哪些技能、投降。是口令，就只回答说话的人，不播放录音，也不进入施法。不是口令，再做开始施法校验。Web
上校验通过并且命令里已有地址，才播放对方原声。技能名对不对，留到施法完成再判。没通过就不播。灵矽不播对方原声。

终端不能提交伤害、治疗、护盾、技能次数、胜负，也不能用自己的时间戳覆盖处理顺序。

玩家停止且没有识别出技能时，终端发送「取消施法」。取消只清除自己的施法中，不打断对方，不消耗次数。

`perfection` 是有限数值，合法范围 0–100，允许小数。省略等于
100。它表示这一次识别给出的技能完成质量。它不决定技能名是否正确，也不改变治疗、护盾、增益、减益、破盾、驱散和行动限制的数值或持续时间。

服务器收到请求后立即处理。不等待对手，不做防抖，也不打开一个两边一起结算的窗口。

开始施法的校验：

1. 回合仍是 `WAITING_CAST`，玩家存活。还在倒数则返回
   `ROUND_NOT_OPEN`。回合已结束或已结算则返回 `ROUND_CLOSED`。玩家已死亡返回
   `ACTOR_DEAD`。这三种都不进入施法中。
2. 本回合被行动限制：返回
   `ACTION_DISABLED`，不进入施法中。打断不会造成这种限制。
3. 该玩家已经处于施法中时，再次开始施法不改变状态，不重新开口播报。
4. 通过后把该玩家标为施法中。此时不匹配技能名，不结算。灵矽不从喇叭播出对方原声。同机双人也不从喇叭播出。

不在施法中时收到取消，不产生效果。

施法完成按下面的顺序校验。前面一步已经返回，就不再做后面的步骤：

1. `command_id` 已经处理过：返回原来的处理结果，不重复结算。同一个 `command_id`
   先省略完成度、再显式提交 100，视为同一条命令。改用另一个完成度重放，返回
   `COMMAND_ALREADY_PROCESSED`。
2. `battle_id`、`round_no` 和玩家身份必须属于当前对局、当前回合。
3. 玩家必须存活。否则 `ACTOR_DEAD`。
4. 本回合被限制行动：返回 `ACTION_DISABLED`，不结算。
5. 还在倒数：返回 `ROUND_NOT_OPEN`，不结算。回合已经不在
   `WAITING_CAST`：该玩家若曾处于施法中，返回 `CAST_INTERRUPTED`；否则返回
   `ROUND_CLOSED`。这两种都不结算，也不再按完成度非法去清除状态。下一回合两边仍可施法。
6. `perfection` 不是有限数值，或超出 0–100：返回
   `INVALID_PERFECTION`。若该玩家处于施法中，清除施法中。
7. 一句里含有该角色两个及以上标准技能名：不生效，清除自己的施法中，对方继续。转写对不上该角色任何一个标准技能名：返回
   `ASR_FAILED`，并清除自己的施法中。对方的施法继续。对得上其中一个，才进入下一步。
8. 技能满足第 3.2
   节的使用规则。否则返回对应的次数或间隔错误，并清除自己的施法中。
9. 原子写入本回合结算者、技能和完成度。若对方仍是施法中，在同一次写入里把对方改为已打断。不记下下一回合禁言。然后把状态改为
   `SETTLING`。写入用的锁和版本见架构设计。

只有这九步全部通过，才结算。玩家自己没在施法中、但回合仍在等待时，一条合法的施法完成视为「开始并立即完成」，同样可以打断已经处于施法中的对方。

Web
在开口时发送开始施法，整句识别完成后再发送施法完成。对方已经处于施法中，这一句被打断，但不锁下一回合。灵矽一次提交整句转写，相当于开始并完成。对方还没有开始施法时，这一句只结算自己。对方之后送到的完成返回
`ROUND_CLOSED`，下一回合双方仍可施法。电脑由服务器在倒数结束时开始施法，玩家的完成可以打断电脑。电脑下一回合仍可开始。

| 校验情况                       | 返回                         | 回合                                  |
| ------------------------------ | ---------------------------- | ------------------------------------- |
| 还在服务器倒数                 | `ROUND_NOT_OPEN`             | 不进入施法中                          |
| 完成度非法                     | `INVALID_PERFECTION`         | 清除自己的施法中，继续等待            |
| 文字不是标准技能名             | `ASR_FAILED`                 | 清除自己的施法中，对方继续            |
| 每局一次的技能已经用过         | `SKILL_EXHAUSTED`            | 清除自己的施法中，继续等待            |
| 基础技能上一回合刚用过         | `BASIC_CONSECUTIVE_REJECTED` | 清除自己的施法中，继续等待            |
| 重复技能的次数或间隔不满足     | `REUSE_LIMIT_REJECTED`       | 清除自己的施法中，继续等待            |
| 自己的施法还没完成，对方先完成 | `CAST_INTERRUPTED`           | 自己的技能不结算。下一回合仍可施法    |
| 回合已经离开施法阶段           | `ROUND_CLOSED`               | 不结算。下一回合仍可施法              |
| 行动者已死亡                   | `ACTOR_DEAD`                 | 不产生施法                            |
| 本回合被石化、麻痹或冻结       | `ACTION_DISABLED`            | 该玩家不能施法，另一方仍可以          |
| 原子写入成功                   | `ACCEPTED`                   | 打断对方施法中的技能，进入 `SETTLING` |

两条施法完成几乎同时到达时，以战斗房间实际处理的顺序为准。本回合只能成功写入一次结算者。客户端的语音开始时间、念完时间和请求发送时间不能覆盖这次写入。

示例：

```text
双方都已开始施法。开始施法时服务器还不知道技能名
服务器先处理到玩家 A 的施法完成「锐刃突刺」，并且该技能当前可释放
玩家 B 此时仍是施法中

结果：
1. B 的施法被打断，不结算，不扣次数。B 的下一回合仍可施法
2. 结算 A 的锐刃突刺
3. B 在本回合之后若再提交施法完成，返回 CAST_INTERRUPTED
4. 战况只告诉 B 吟唱被打断和这一击的血量，然后倒数。倒数结束，两边都可以念
```

先被处理的施法完成会完整结算。后完成的技能不再结算。长技能对长技能同样如此：谁的施法完成先被处理，谁生效，另一方被打断。

### 4.4 战斗阶段

状态从 `WAITING_CAST` 改为 `SETTLING`
后，结算者和技能锁定。对方被打断的技能不再进入结算。服务器用配置里的
`skill_id`、`effect_version`、本回合保存的完成度，以及结算者当前状态计算：

1. 确定目标和效果参数。
2. 计入行动者身上的增益、生命、护盾和其他状态。
3. 按配置顺序应用伤害、护盾、治疗、增益、减益、持续伤害、破盾、驱散或行动限制。
4. 把生命、护盾和状态限制在上限内。生命最低为 0。护盾最低为 0，最高 500。
5. 记录技能使用次数和最近使用回合。

直接伤害：

```text
最终伤害 = 四舍五入(
  技能基础伤害
  × perfection / 100
  × 行动者伤害增益
  × 行动者伤害降低
  × 目标伤害减免
  × 目标受到伤害提高
)
```

没有对应增益或减益时，该乘数为 1。最终伤害最低为 0。先扣目标护盾，再扣目标生命。

示例：基础伤害 65，没有其他增减益，完成度 90。`round(65 × 0.9) = 59`。

多段 `DAMAGE`
的每一段都用同一个完成度计算。持续伤害保存施加它的那次行动的完成度，以后每次结算都用这个值。后续回合不能提交新的完成度去修改已经存在的持续伤害。

治疗、护盾、增益、减益、破盾、驱散和行动限制不乘完成度。

结算完成后，服务器先持久化结果和事件，再向双方发送同一份权威结果。至少包括：

- 本回合行动的玩家和角色。
- 标准技能名和 `skill_id`。
- 伤害、治疗、护盾和其他效果明细。
- 结算前后的双方生命、护盾和状态摘要。
- 是否已经产生死亡或终局。

事件名为 `ACTION_ACCEPTED` 和 `BATTLE_RESULT`。

战斗阶段已经使对局结束时，立即进入第 4.6
节的结束处理，不执行本回合的回合结束效果。

### 4.5 回合结束

战斗阶段的结果已经持久化，且对局仍在进行时，状态改为 `ENDING`，按第 4.2
节的五步处理。

- 结束效果使一方生命 ≤ 0：结束对局，不创建下一回合。
- 双方仍存活：记录 `ROUND_FINISHED`，发送完整回合结果。终端播完战况并回执后进入
  `COUNTDOWN`，倒数结束才创建下一回合并回到 `WAITING_CAST`。
- 本回合结算者不再改变。被打断的技能不能在回合结束阶段补结算。
- 回合结束效果不额外消耗技能次数，除非某个效果的配置明确把它定义成一次新的技能行动。首版没有这种效果。
- 双方都无法行动时，本回合没有技能行动，仍然执行回合结束效果。持续伤害和周期治疗仍会结算。

### 4.6 胜负

以下情况结束正式对局：

| 条件                                   | 结果                                                                                                         |
| -------------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| 一方生命 ≤ 0，另一方 > 0               | 生命大于 0 的一方胜                                                                                          |
| 双方生命都 ≤ 0，且按效果顺序能区分先后 | 按该顺序记录胜负                                                                                             |
| 双方生命都 ≤ 0，且无法区分先后         | 平局                                                                                                         |
| 玩家认输，或主动离开                   | 对方胜。尚未完成的施法直接取消，不结算。已经进入 `SETTLING` 的技能先结算；这次结算已经分出胜负时，沿用该结果 |
| 断线超过 10 秒仍未重连                 | 视为离开，对方胜                                                                                             |
| 房间发生不可恢复的服务器异常           | 异常结束。不伪造胜负                                                                                         |

双方一直存活，就继续下一回合。

结束时服务器：

1. 标记死亡角色和胜负原因。
2. 将对局状态设为 `FINISHED`，拒绝后续战斗指令。
3. 持久化最终快照、技能使用记录和 `BATTLE_FINISHED`。
4. 向双方发送胜者、败者、最终状态和结束原因。胜负双方听到各自视角的主持。
5. 战斗记录改为只读归档，清理房间运行态。

客户端离开结算后回到准备。下一局必须新建 `battle_id`。

### 4.7 完成度

| 规则     | 约定                                                             |
| -------- | ---------------------------------------------------------------- |
| 合法范围 | 0–100 的有限数值，可含小数                                       |
| 省略     | 与提交 100 的结算结果相同                                        |
| 非法     | `INVALID_PERFECTION`。不消耗技能，不推进回合                     |
| 影响范围 | 直接伤害，以及持续伤害的基础伤害                                 |
| 不影响   | 技能名是否匹配；治疗、护盾、增减益、破盾、驱散、行动限制         |
| 重放     | 同一 `command_id` 换一个完成度，返回 `COMMAND_ALREADY_PROCESSED` |

学习和对战使用同一公式。练习里听到的伤害，就是这句技能在相同状态下、相同完成度会打出的伤害。

## 5. 进入对战

三种对战进入不同，进入之后使用同一套回合规则。身份在进房时确定。战斗指令不能改写座位。账号与已购角色见设计文档。一场里谁开口、谁发倒数，见交互设计的时序。

### 5.1 准备

1. 玩家选择一个角色。未选角色不能完成准备。
2. 客户端展示该角色的 1 个基础技能、6 个角色技能、效果和使用规则。
3. 玩家可以说「准备」。
4. 对局状态为 `PREPARING`。双方各自有准备标记。
5. 服务器按 `character_id`
   读取配置，并复核技能名唯一、无同音冲突、无别名、无快捷词。
6. 双方都准备之前，不创建第一回合，不接受战斗指令。

双方准备完毕后，服务器初始化快照：生命 1000、护盾
0、技能次数清空、没有状态效果。然后将对局改为 `RUNNING`，创建第 1 回合，广播
`BATTLE_STARTED` 和 `ROUND_STARTED`。

对电脑时，电脑座位在创建对局时视为已选角、已准备。人类玩家准备完毕即开战。

### 5.2 对电脑

一个玩家座位，一个电脑座位。Web 和一台灵矽都可以进入。

电脑使用玩家选中的对手角色。玩家未指定时，使用烈焰剑士。电脑的生命、护盾、技能次数和状态与玩家遵守同一配置。

电脑不绕过校验，也不能直接改写生命。服务器倒数结束、回合进入可施法后，电脑才选定技能并开始施法。被打断只取消电脑这一句，下一回合倒数结束后电脑仍会开始。终端播放该技能的咒语语音，每个汉字
400 毫秒。Web 在语音结束时提交电脑的施法完成。灵矽在语音结束后再等 2
秒才提交，把转写和工具调用算进去。语音被打断时立刻停，到点后的完成不再结算。当时被行动限制，就等到限制解除后的下一个可施法回合再开始。玩家的施法完成可以在电脑完成之前先到。先到则电脑被打断。下一回合电脑仍可开始。

玩家之间也等同一次服务器倒数结束才开始抢。倒数结束后，谁先把技能念完并送到服务器，谁生效。一方开始施法后，另一方听到的是他正在念的咒语语音。

首版选技能的策略固定，并写入测试：

1. 在该角色当前可释放的技能中，若基础技能可用，使用基础技能。
2. 基础技能不可用时，使用名称最短的一张可释放角色技能。
3. 长度相同则按该角色技能配置顺序取第一张。

策略以后可以换成不同风格。换风格不能换成另一套结算。

### 5.3 同机双人

仅灵矽，一台设备，一只麦。两个人同时念，规则与联机相同：先被处理的合法施法完成结算，并打断对方还在施法中的那一句，不锁下一回合。设备能同时认出两个人，就把两句都送上。做不到也没关系，先被识别出来的那一句参加这一回合的抢先。

1. 两位玩家各说一句，声纹绑定到座位甲、座位乙。认不出说话人时不提交。
2. 各自选择角色，各自准备。
3. 开战之后两人同时念。声纹用来确认这句话是谁的。识别出谁，就把谁的转写送上。
4. 这一句不是合法技能时，只拒绝这一句，另一人若还在施法中则继续。
5. 被行动限制的人不能开始施法。另一个人照常可以念。

录音不从这只喇叭播出。伤害和胜负仍按同一套结算。说法见交互设计。

### 5.4 联机

两个独立会话，一个四位房间号。

1. 一方开房，并听到房间号。
2. 另一方说出这四位数字加入。
3. 各自选角、准备。
4. 双方都准备后开战。加入、选角和准备都由服务器通知另一边。双方都准备之前不倒数。说法见交互设计。

身份按各自的会话区分。首版一个房间的两端是同一类终端：Web 对
Web，或灵矽对灵矽。两边规则相同。进入同一 `battle_id`
的两端读写同一份服务器快照。

开房不消耗技能，也不发送
`ROUND_STARTED`。任一方在准备完成前离开，房间不进入战斗。四位房间号怎么听、怎么说，见交互设计。

## 6. 裁决边界

快照怎么存、命令长什么样、拒绝码怎么返回，见架构设计。这里只规定谁有权裁决。

### 6.1 谁做什么

终端负责：

- 麦克风采集，以及把语音交给识别系统。
- 取得转写文字和 0–100 的完成度。
- 展示或播报候选技能。
- 播放主持、技能音效和结算。
- 灵矽同机双人时，先用声纹标出座位。

识别由灵矽或 Web 终端完成。Game server
不从录音重做转写，也不从录音重算完成度。技能名只看转写文字是否与标准技能名完全一致。灵矽的录音地址只用于播放，取不到时不挡住结算。

大模型负责：

- 在大厅把「对电脑」「角色名」「开房间」「房间号」「准备」「复盘」「练习」等话对应到功能。说法见交互设计。
- 没有对方录音时，照念服务器已经写好的短句。不改字，不自己倒数。

大模型不负责：

- 判断技能名是否匹配、该不该结算、对方的施法要不要被打断。
- 计算伤害、治疗、护盾、状态和胜负。
- 在主持词里添加结算里没有的效果。
- 自己倒数，或在战况回执之前打开下一回合。

战斗服务器负责：

- 创建房间、准备、开战和推进回合。
- 把对手加入、选角和准备通知另一边。双方都准备之前不倒数。
- 发送倒数「三。二。一。」并按时钟开窗。收到需要出声的一侧的战况回执，或等待超过
  5 秒，才发倒数。
- 对局中从转写里区分看血、还有哪些技能、投降和施法。口令只回答说话的人。
- 验证技能是否属于当前角色，以及次数和间隔。
- 按处理顺序决定哪一条施法完成生效，并打断对方尚未完成的施法。
- 计算效果，更新生命、护盾、技能使用记录和状态。
- 判定胜负。
- 记录完整战斗日志。先写盘，再广播。

### 6.2 一份权威快照

每场对局以 `battle_id` 保存一份服务端快照，并带有单调递增的
`version`。请求不能携带或覆盖生命、护盾、状态、技能次数和回合结果。同一对局的命令串行执行，先写盘再广播。版本冲突时不得结算第二个技能，也不得连跳两个阶段。怎么加锁、怎么存，见架构设计。

### 6.3 要记住的状态

```text
Battle
- battle_id
- mode                  VS_CPU / LOCAL_DUO / ONLINE
- status                PREPARING / RUNNING / FINISHED / ARCHIVED
- round_no
- round_status          COUNTDOWN / WAITING_CAST / SETTLING / ENDING / FINISHED
- round_actor_id        本回合结算技能的玩家
- perfection            本回合结算技能的完成度，默认 100
- settlement_sequence
- version

PlayerBattleState
- player_id
- character_id
- hp
- shield
- alive
- action_state          READY / ACTION_DISABLED
- cast_state            IDLE / CASTING / INTERRUPTED
- skill_usage
- skill_last_used_round
- status_effects

CastCommand
- command_id
- battle_id
- round_no
- player_id
- kind                  BEGIN / CANCEL / COMPLETE
- skill_id              仅 COMPLETE 且匹配成功后才有
- transcribed_text
- perfection
- received_at
- state
- reject_reason
```

战斗日志要能还原每一次开始施法、取消、施法完成、打断、结算和拒绝原因。对外查询返回快照的副本。调用方改副本，不能改真实对局。

练习模式不写入上述正式对局状态。

## 7. 异常

| 场景                                       | 处理                                                                                                                                                                           |
| ------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 语音没有文字，或文字不匹配                 | 清除自己的施法中。`ASR_FAILED`。对方继续念                                                                                                                                     |
| 念到一半停止                               | 终端发送取消。自己的施法清除，对方继续                                                                                                                                         |
| 一句里有两个技能名                         | 清除自己的施法中。玩家听到「一次一道。」                                                                                                                                       |
| 技能已用过，或基础技能连用，或重复间隔不够 | 不结算，不扣次数                                                                                                                                                               |
| 对方的施法完成先被处理                     | 自己的技能被打断。`CAST_INTERRUPTED`。不扣次数。下一回合仍可施法                                                                                                               |
| 本回合被石化、麻痹或冻结                   | `ACTION_DISABLED`。不能开始施法，不扣次数。另一个人仍可施法                                                                                                                    |
| 技能附带持续伤害、增益、减益或行动限制     | 由服务器写入状态，按持续回合结算                                                                                                                                               |
| 破盾或驱散时目标没有对应状态               | 记录 0 效果。这次施法仍成功，不返还次数                                                                                                                                        |
| 同一 `command_id` 重试                     | 返回原结果。不重复打断，不重复造成伤害                                                                                                                                         |
| 同一 `command_id` 换完成度                 | `COMMAND_ALREADY_PROCESSED`                                                                                                                                                    |
| 单回合长时间无人念完                       | 不触发玩法超时。继续等待                                                                                                                                                       |
| 客户端断线                                 | 保留战斗状态，等待 10 秒重连。未完成的施法保留到超时                                                                                                                           |
| 10 秒内重连                                | 以服务器快照为准。终端用一句现状说明血量和现在能不能开口，不报回合号，不逐条补播。若窗口还没开，再念一次倒数，开窗时刻不变。当前回合因打断不能施法时，直接说明这一回合不能行动 |
| 超过 10 秒未重连，或玩家主动离开、投降     | 对方胜。尚未完成的施法取消。已经进入 `SETTLING` 的技能先结算；这次结算已经分出胜负时，沿用该结果                                                                               |
| 服务器结算失败                             | 房间暂停并重试。不允许终端自己补算                                                                                                                                             |
| 不可恢复的服务器异常                       | 异常结束。不伪造胜负                                                                                                                                                           |
| 双方都因行动限制无法施法                   | 本回合不产生技能，直接做回合结束效果                                                                                                                                           |

重连后的展示以服务器快照为准。终端本地预识别可以用来降低等待感，服务器仍然重新匹配技能名。

## 8. 验收

1. 相同技能在相同状态、相同完成度下，服务器计算结果一致。
2. 客户端伪造伤害、治疗、护盾或技能次数，不能改变战斗结果。
3. 双方可以同时处于施法中。先被处理的合法施法完成结算，并打断对方尚未完成的施法。被打断的技能不结算、不扣次数。下一回合两边仍可施法。
4. 获胜技能只结算一次。结算完成并持久化之后，才进入回合结束或对局结束。后到的施法完成返回
   `CAST_INTERRUPTED` 或 `ROUND_CLOSED`。
5. 每局一次的技能，第二次施法完成被拒绝。基础技能不能在连续两个回合成功结算。有限重复技能遵守次数和最小回合间隔。
6. 识别失败、取消、被打断、次数不足和非法完成度不扣技能次数，也不让对方的施法中断，除非自己的施法完成已经通过校验。
7. 同一个 `command_id` 不能重复造成伤害或重复打断。省略完成度与提交 100
   结果相同。超出 0–100 或不是有限数值时返回 `INVALID_PERFECTION`。
8. 完成度只缩放直接伤害和持续伤害。复合技能里的治疗、护盾、增减益、破盾、驱散和行动限制保持配置值。
9. 治疗不超过 1000。护盾不超过 500。伤害先扣护盾，再扣生命，最低为 0。
10. 增益、减益、持续伤害和周期治疗按配置的回合数或触发次数结算，到期后移除。本回合刚附加的状态，不在本回合结束时立刻扣持续时间。
11. 打断只取消尚未完成的施法。已经进入结算的技能会完整结算。石化、麻痹和冻结只阻止下一回合开始施法，不取消已经进入结算的技能，也不叠加多层行动限制。双方都被限制时，本回合没有技能，仍执行回合结束效果。
12. 战斗阶段已经分出胜负时，不再执行该回合的结束效果。
13. 一方生命 ≤ 0 且另一方仍存活时，存活方胜。双方都 ≤ 0
    且顺序无法区分时为平局。双方一直存活时，战况播完，由服务器倒数结束后才进入下一回合。
14. 断线后 10
    秒内重连，状态以服务器快照为准。超时、投降或主动离开，对方胜；已经进入结算的技能先结算，这次结算已经分出胜负时沿用该结果。服务器不可恢复异常不伪造胜负。
15. 技能名存在同音字、同音词或同音别名时，内容校验拒绝发布。自定义快捷词不能匹配成功。
16. 每个角色恰好 1 个基础技能和 6 个角色技能。
17. 不同网络延迟下，结果以服务器处理「施法完成」的先后为准。服务器不增加防抖，也不因为两条完成靠得很近就让两边都结算。
18. 对电脑在倒数结束后播放咒语语音，每个汉字 400 毫秒。Web
    在语音结束时提交完成。灵矽再等 2
    秒后提交。玩家先完成则电脑被打断，语音停掉。电脑不能直接改写生命、护盾或胜负。
19. 学习与对战使用同一套技能名匹配和完成度公式。练习不写入正式对局。

## 9. 已确定的约束

- 单局，不打三局两胜。
- 每个角色固定 1 个基础技能和 6 个角色技能。
- 语音识别在终端侧完成。服务器接收转写文字和完成度。
- 单回合、单局都不设玩法时长。
- 一回合只结算一个技能。Web、两台灵矽和同机双人都同时施法。先被处理的合法施法完成生效，并打断对方尚未完成的施法。
- 已经进入结算的技能会完整生效。被打断不扣技能次数，也不锁定下一回合。行动限制仍按回合阻止开始施法，这是技能效果，不是打断的附加惩罚。
- 技能名不得包含同音字、同音词或别名。不支持自定义快捷词。
- 服务器收到请求后立即校验。同一回合只结算一个技能。
- 开战和每一回合之后，由服务器倒数 3、2、1，结束后才可施法。对电脑的计时见第 5.2
  节。灵矽只提交转写和完成度。对方的录音只在战况回执前已经拿到地址时播放，不推迟倒数。录音不参与结算。同机也同时念。能同时认出两个人就把两句都送上。做不到时，先被识别出来的那一句参加抢先。
- 技能匹配、打断、数值和胜负只由服务器规则决定。
