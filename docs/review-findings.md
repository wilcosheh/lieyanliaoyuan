# 烈焰燎原 · 灵矽生产实连评审

评审只覆盖灵矽 MCP 的三条场景：练习技能、人机对战、两人联机。生产地址是
`https://acqvpmrtdxtwsfendxrd.supabase.co/functions/v1/game/mcp?key=***`。连接密钥已打码。没有改玩法数值，也没有改线上配置。线上
Web 本次不评。

实测时间：2026-10-25。调用方式是带正确密钥的 `POST` JSON-RPC
`tools/call`（`submit_lobby_text`、`submit_utterance`、`begin_cast`、`wait_event`）。单次工具返回大约
4.5–12 秒。`clips` 和 `funcs` 在全部成功响应里都是空数组，没有编出 `linx_play`。

鉴权抽查：不带 key、错误 key 的 `GET /mcp` 都是 `401`，正文 `unauthorized`。正确
key 的 SSE 返回 `200`，首帧是 `event: endpoint`，指向
`/functions/v1/game/mcp/message?sessionId=…&key=***`。`GET …/mcp/health` 返回
`{"ok":true}`。`tools/list` 是这 6
个工具：`submit_lobby_text`、`submit_utterance`、`begin_cast`、`cancel_cast`、`ack_playback`、`wait_event`。

下面每段都按「预期 → 实测 → 缺口」写。预期以
`docs/交互设计.md`、`docs/gameplay-design.md` 和 `docs/架构设计.md`
里灵矽主路径为准。第 1–4 节是 2026-10-25 修之前的生产实连记录，保留作对照。

本地同构路径是 `createMcpServer` 的 Streamable HTTP
`POST`（`accept: application/json`），引擎和线上同一套
`GameEngine`。数据库枢纽的超时用 `settleHubCall`
单测：预算到点后若原调用随后返回，仍交回引擎原句，不交「刚才没听清」。没有起
Postgres，所以 SqlHub / RestHub 的真实连库超时没有在本地打到库上。

部署后复验（同一地址，`key` 打码，不要改密钥或配置）：

1. 不带 key、错误 key 仍是 `401`。正确 key 做下面三步，每步都看
   `structuredContent.say`，不要只看模型转述。
2. 人机：`对电脑` → 选角 → `准备`，听到「三。二。一。」。开窗后立刻
   `看血`，或等超过电脑出手时间再
   `看血`。这一拍必须是血量/护盾/能不能开口，不能是「中了某招」。电脑那一击应出现在随后的
   `wait_event`。先 `begin_cast`
   再在电脑截止之后交技能，应听到「吟唱被打断。中了某招。你…血。对手…血。」，不能只有「吟唱被打断。」或只有「中了某招」。
3. 断线：人机开战后代停超过 10 秒，换一个新的 `mcp-session-id` 再
   `看血`，应听到「你输了。」并进入 `REVIEW`。同一会话里停超过 10 秒再
   `看血`，不应因此判负。10 秒内重连应听到「回来了。」加现状。
4. 联机：一台
   `开房间`，另一台用四位号加入。两边选角、`准备`。后准备的一侧和挂着等待的一侧都要听到开战和「三。二。一。」，不能是「刚才没听清」或空
   `say`。一侧
   `begin_cast`，另一侧念完合法技能。命中侧听到「技能名命中」和双方血量/护盾；被打断侧听到「吟唱被打断。中了技能名。」以及自己的血量/护盾。然后
   `投降`：认输方「你输了。」，对方「你赢了。」，都带双方血量。

剩余风险：调用若比预算再多挂 5
秒仍不返回，而且快照里还没有这条命令，兜底句仍会出现。战况按交互设计说技能名和双方血量、有护盾时说剩余护盾，不另报伤害点数。技能伤害表没有改。

## 1. 练习技能

### 1.1 进入练习

**预期：** 没选角不能练。选角后报出该角色 7
个技能名，进入练习。练习不建对局、不计胜负。

**实测：**

| 原话                        | 返回                                                                                                                    |
| --------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| `练习`（还没选角）          | `CHARACTER_REQUIRED`。`先说角色名。可选烈焰剑士、圣光守卫、暗影术士、风行弓手。` 阶段仍是 `LOBBY`                       |
| 先说 `烈焰剑士` 再说 `练习` | 阶段 `PRACTICE`。`破风斩、锐刃突刺、焰步追击、裂甲连环斩、战意燃锋诀、血刃追魂印、焚天裂空万刃归一。直接念技能名练习。` |
| 改说 `圣光守卫` 再说 `练习` | 同样进入 `PRACTICE`，改报守阵重击、护阵回击、安魂微光、圣甲护身诀、回春守势诀、圣光净化万象咒、神圣壁垒永昼长明         |
| `结束练习`                  | `练习结束。说对电脑打一局，或开房间。` 回到 `LOBBY`                                                                     |

`wait` 为 false，`ack_required` 为 false。没有血量，没有胜负。

**缺口：**
无。进练习和结束练习与交互文案一致。P2：没有木桩，练的时候听不见「对方中了这一招」。

### 1.2 念技能、完成度、可重复

**预期：**
转写必须和标准技能名完全一致。念对才报完成度和按完成度缩放后的直接伤害；治疗、护盾不按完成度打折。没念对说「咒语没成。」一句里两招说「一次一道。」练习不消耗次数，可以马上再念。

**实测：**

| 原话                  | 返回                                            |
| --------------------- | ----------------------------------------------- |
| `破风斩`              | `完成度100。破风斩。造成65点伤害。`             |
| `破风站`              | `完成度67。破风斩。造成44点伤害。` 被收成破风斩 |
| `破风斩` 且完成度 50  | `完成度50。破风斩。造成33点伤害。`              |
| `圣甲护身诀`          | `完成度100。圣甲护身诀。获得210点护盾。`        |
| 立刻再念 `圣甲护身诀` | 同一句。没有「已经用过」，没有胜负              |
| `战意燃锋诀`          | `完成度100。战意燃锋诀。已记下。`               |
| `你好`                | `ASR_FAILED`。`咒语没成。`                      |
| `破风斩锐刃突刺`      | `AMBIGUOUS_SKILL`。`一次一道。`                 |

伤害句把技能名和点数说清楚了。护盾句说了「获得 210
点护盾」，但没说这招还带减伤。增益技能只说「已记下。」近音字被当成命中，完成度按汉字重合算（破、风中了，站没中，约
67；65×67% 四舍五入是 44）。显式完成度 50 时，65×50% 四舍五入是 33，和返回一致。

练习里没有对手，所以没有打断，也没有「对我造成多少伤害」。这和「练习不创建对局」一致。

**缺口：**

| 级别 | 缺口                                                                                                                                                                              |
| ---- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| P1   | 近音「破风站」被结算成破风斩。产品要求标准技能名完全一致，运行时 `matchSkill` 会做拼音和别名纠偏。练习把纠偏后的重合度当成完成度；对战里若终端省略完成度，同一套纠偏会按 100 结算 |
| P1   | 增益、复合效果听不全。`practiceSay` 只描述 `effects[0]`。战意燃锋诀变成「已记下。」圣甲护身诀的减伤没有出现在句子里                                                               |
| P2   | 没有木桩。玩家听得见「造成 65 点」「获得 210 点护盾」，听不见这招打在人身上时谁掉血、护盾吸了多少                                                                                 |

反馈时机：当次工具返回就有句子，大约 4.5–5 秒。没有额外音频。

## 2. 人机对战

设备只说「对电脑」，没有指定电脑角色。电脑固定是烈焰剑士。玩家选了圣光守卫。另一局玩家选烈焰剑士、电脑也是烈焰剑士，用来看掉血。

### 2.1 开局和 321

**预期：** 准备后先听到双方 1000
血和落败条件，再听服务器的「三。二。一。」倒数结束才能念。电脑按字数 × 400
毫秒出手，语音端再加 2 秒。

**实测：** `准备` 返回阶段 `BATTLE`，`opens_in_ms` 为 3000，`ack_required` 为
false，`wait` 为 true：

`双方各1000血。血量先到0的一方落败。三。二。一。`

句子和交互设计一致。没有电脑咒语的播放地址。

**缺口：** P1。架构要求电脑预备语音编成 `linx_play`。生产返回的 `clips`、`funcs`
一直是空的，喇叭侧只有主持文本，没有电脑念咒声。

### 2.2 玩家念咒、电脑出手、打断和命中

**预期：**
开窗后谁的合法施法先被处理，谁结算，并打断还在念的另一方。玩家要听见电脑用了哪一招、自己掉了多少血或护盾。

**实测：**

准备一返回就提交 `圣甲护身诀`（不再在客户端多等 3 秒）：

`圣甲护身诀命中。你1000血。护盾210。对手1000血。三。二。一。`

这一击是玩家自己的，技能名在，护盾结到 210，并立刻带下一轮倒数。

接着发 `看血`。返回的不是看血，而是电脑已经打完的一击：

`中了破风斩。你1000血。护盾158。对手1000血。三。二。一。`

再等 4 秒后提交 `守阵重击`，自己的招没有生效，回来的仍是电脑的招：

`中了锐刃突刺。你1000血。护盾94。对手1000血。三。二。一。`

另一局（玩家烈焰剑士）在倒数之后先等 3.3 秒再 `begin_cast`，返回直接是：

`中了破风斩。你935血。对手1000血。三。二。一。`

随后提交的 `锐刃突刺`、`看血`、以及断开 12 秒后用新会话再说的 `看血`，依次变成：

| 玩家本意      | 实际听到                                          | 血量变化   |
| ------------- | ------------------------------------------------- | ---------- |
| `begin_cast`  | `中了破风斩。你935血。对手1000血。三。二。一。`   | 1000 → 935 |
| `锐刃突刺`    | `中了锐刃突刺。你855血。对手1000血。三。二。一。` | 935 → 855  |
| `看血`        | `中了破风斩。你790血。对手1000血。三。二。一。`   | 855 → 790  |
| 新会话 `看血` | `中了焰步追击。你715血。对手1000血。三。二。一。` | 790 → 715  |

没有出现「吟唱被打断。」玩家晚到的句子被电脑结算替换掉了。

护盾那局的数字对得上减伤，但句子里没说：圣甲护身诀带 20% 减伤时，破风斩 65
先变成 52，210−52=158；锐刃突刺 80 先变成
64，158−64=94。播报只有剩余护盾，没有「造成多少」「护盾吸收多少」「减伤」。

电脑出手顺序和 `chooseCpuSkill`
一致：能放基础技能就放破风斩，基础技能不能连着放时改放最短的角色技能（锐刃突刺、焰步追击）。

空挂一次 `wait_event` 约 22 秒，只返回 `。`，而且阶段被标成
`LOBBY`。电脑出手不会在玩家沉默时推过来，要等下一次开口才嵌进那个响应，并马上再数「三。二。一。」

**缺口：**

| 级别 | 缺口                                                                                                                                                                     |
| ---- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| P0   | 边缘函数一次调用大约 5–12 秒，电脑在开窗后大约 3.2 秒（3 字×400 毫秒 + 2 秒）就出手。玩家稍慢，`看血` 和自己的技能句都会被换成「中了某招」。听不见拒绝原因，也抢不到打断 |
| P1   | 对方招式名有（「中了破风斩」「圣甲护身诀命中」），对我造成的伤害没有点数。护盾只报剩余值，不报吸收了多少，不报减伤或增益的名字                                           |
| P1   | 电脑出手不主动推给正在 `wait_event` 的一侧。空等只有句号                                                                                                                 |
| P1   | 没有电脑原声。`linx_play` 没有出现                                                                                                                                       |

### 2.3 状态、认输、断线、复盘

**预期：**
看血要报领先或落后、双方生命、护盾、现在能不能开口。认输对方胜。断线超过 10
秒未重连，对方胜。复盘先说胜负和最终血量，再说最后三击。

**实测：**

- 人机过程中的 `看血` 没有走状态句，被电脑的新一击占掉（见上表）。
- `投降` 成功：`你输了。你1000血。对手1000血。说再来一局，或复盘。` 阶段
  `REVIEW`。血还在 1000 也判负，认输本身成立。
- `复盘`：`你用了圣甲护身诀。你输了。`
  没有最终血量，没有电脑用过的破风斩、锐刃突刺，也没有「最后三击」。
- 断线：第一局开战后代打到 715 血，停 12 秒再换一个 MCP 会话说
  `看血`。没有「回来了」，没有判负，电脑又打出焰步追击。`GameEngine.refresh` 把
  `disconnectDeadline` 固定写成 `null`，时钟里的断线到期不会发生。

**缺口：**

| 级别 | 缺口                                                                                   |
| ---- | -------------------------------------------------------------------------------------- |
| P0   | 断线超过 10 秒不判负，重连也不说「回来了」。局继续走，电脑照旧出手                     |
| P1   | 复盘听不见对手招式和最后三击，也没把最终血量再说一遍                                   |
| P1   | 对战中的「看血」不稳定。人机里它经常变成电脑的新战况，而不是双方血量、护盾和能不能开口 |

## 3. 两人联机

成功走完的一局房间号是 2899（播报为
`2、8、9、9`）。房主设备与客人设备各一条会话。房主烈焰剑士，客人圣光守卫。此前用错误号码
`0000` 加入，返回 `没有这个房间。`，这是预期内的拒绝，不记成缺陷。空房上把
`wait_event` 挂超过 25
秒，客户端超时断开，接着几条命令变成「刚才没听清」；房主说「退出」后得到
`已离开房间。`

### 3.1 建房

**预期：** 「开房间」得到四位号码，数字用顿号分开，并进入等待。

**实测：** `房间号 2、8、9、9。把号码告诉对手。等对手加入。` 阶段
`LOBBY`，`wait` 为 true。约 5.2 秒返回。另一间曾报出 `6、6、9、1`，格式相同。

**缺口：** 无。建房文案符合交互设计。

### 3.2 进房

**预期：**
客人报四位号码后听到「已加入。请选角色并准备。」房主听到「对手来了。请选角色并准备。」

**实测：**

- 客人 `加入房间，房间号2899`：`已加入。请选角色并准备。` 约 10
  秒。进房本身成功。
- 随后房主 `wait_event` 约 12 秒，`code` 仍是 `ACCEPTED`，`say`
  是空字符串。没有「对手来了。」

**缺口：**
P1。客人进房的原句是对的，房主这一拍没有听到对手已经进来。后面的选角通知是夹在别的句子里补出来的，不是进房当时的推送。

### 3.3 选角和就绪

**预期：**
各自说角色名。对方听到「对手选了某角色。」双方都说准备后，后准备的一侧开战，另一侧也应听到同一句开战和「三。二。一。」

**实测：**

| 步骤           | 调用方实际听到的                              | 服务器后来表现出的状态                                   |
| -------------- | --------------------------------------------- | -------------------------------------------------------- |
| 房主说烈焰剑士 | `刚才没听清，请再说一次。` 阶段被标成 `LOBBY` | 之后能准备，角色已留下                                   |
| 客人说圣光守卫 | 同样是 `刚才没听清，请再说一次。`             | 房主下一句里出现了「对手选了圣光守卫。」                 |
| 房主准备       | `对手选了圣光守卫。你已准备。等对手准备。`    | 准备成功，选角通知是补在这句前面的                       |
| 客人准备       | 又是 `刚才没听清，请再说一次。`               | 房主接着等到的 `wait_event` 已经是开战句，说明准备已生效 |

「刚才没听清，请再说一次。」是数据库枢纽调用失败时的兜底句（`SqlHub` / `RestHub`
的
fallback），不是引擎拒绝选角。状态已经写上，调用方却听到失败。单次这类调用大约
12 秒。

**缺口：**
P0。选角和准备会在玩家听到失败句的同时生效。灵矽若照念「刚才没听清」，玩家会再选一次或以为还没进局。

### 3.4 321

**预期：** 双方都准备好以后，两边都听到
`双方各1000血。血量先到0的一方落败。三。二。一。` 倒数约 3 秒，结束后才能念。

**实测：** 客人自己的准备响应不是开战句。房主在客人准备之后再 `wait_event`，约
11.5 秒得到：

`双方各1000血。血量先到0的一方落败。三。二。一。`

阶段 `BATTLE`，`opens_in_ms` 为 3000，`ack_required` 为
false。开战文案是对的，但只出现在当时挂着等待的房主这一侧。客人那一拍听到的是失败兜底句。

**缺口：** P0。321 没有同时交到双方。没挂上
`wait_event`、或者这次调用走了兜底的那一侧，听不到可以发动招式。

### 3.5 念咒、打断、命中

**预期：**
房主先开口（`begin_cast`），客人念完圣甲护身诀则客人这招结算，房主听到自己被打断，并听到客人用了什么、自己血量或护盾怎么变。客人听到自己的技能名和护盾。

**实测：**

| 步骤              | 返回                                                                      |
| ----------------- | ------------------------------------------------------------------------- |
| 房主 `begin_cast` | `ACCEPTED`，`say` 为空，`wait` 为 false。约 11 秒。开口标记本身可以是空句 |
| 客人 `圣甲护身诀` | 调用方听到 `刚才没听清，请再说一次。` 阶段却被标成 `LOBBY`                |
| 房主接着 `破风斩` | `CAST_INTERRUPTED`。只有 `吟唱被打断。` 没有技能名，没有血量，没有护盾    |

随后两边 `看血`：

- 客人：`你1000血。对手1000血。你护盾210。对手护盾0。还不能开口。`
- 房主：`你1000血。对手1000血。你护盾0。对手护盾210。还不能开口。`

所以客人的圣甲护身诀确实结算了（自己 210 护盾，对方
0），房主的破风斩被打断，没有打掉血。双方血量都还是
1000。「还不能开口」说明新的一轮倒数还没结束。

对方招式和伤害，在出招那一拍两边都没听到：

- 客人没有听到「圣甲护身诀命中」或「获得 210 点护盾」。
- 房主没有听到「中了圣甲护身诀」，也没有听到 0
  伤害或护盾变化。打断句只有四个字。
- 要再发一次 `看血`，才从剩余护盾推断出客人上了盾。看血仍然不提技能名。

**缺口：**

| 级别 | 缺口                                                                                                                            |
| ---- | ------------------------------------------------------------------------------------------------------------------------------- |
| P0   | 命中的那一侧经常只听到「刚才没听清」，被打断的那一侧只听到「吟唱被打断。」对方发动了什么、对我造成了什么，在结算当拍都缺失      |
| P1   | `看血` 能补上双方生命和护盾，以及现在能不能开口，但仍不提上一招的名字、伤害点数、吸收量或状态名。时机晚一轮，而且要玩家自己再问 |
| P1   | 人机里「命中 / 中了 + 技能名 + 剩余血量护盾」至少还在同一句里。联机这一局连技能名都没有推进调用方的返回                         |

### 3.6 胜负结算

**预期：**
认输后认输方听到「你输了」和双方血量，对方听到「你赢了」。已经进结算的技能先算完。

**实测：** 房主说 `投降`，调用方听到的又是 `刚才没听清，请再说一次。` 客人接着
`看血`，返回 `PHASE_REJECTED`，阶段已经是 `REVIEW`，`say`
仍是空字符串。局已经结束（阶段进了复盘），但认输方没听到输，获胜方没听到赢，也没听到最终血量和护盾。

这一局因此没有听到完整胜负句。人机那一局的 `投降`
是听到了「你输了。……说再来一局，或复盘。」的，说明引擎句子存在，联机这条被枢纽兜底盖住了。

**缺口：** P0。联机认输已经改了阶段，双方都没有听到胜负播报。

## 4. 对方招式和对我伤害（人机、联机对照）

练习没有对手。人机和联机单独看「对方用了什么」和「对我怎样」：

| 场面                         | 对方招式名                       | 对我造成的伤害或吸收                                    | 时机                                     |
| ---------------------------- | -------------------------------- | ------------------------------------------------------- | ---------------------------------------- |
| 练习，伤害或护盾技能         | 没有对手                         | 有示范点数：「造成 65 点」「获得 210 点护盾」           | 当次返回，约 5 秒                        |
| 练习，增益技能               | 无                               | 没有。只说「已记下。」                                  | 当次返回                                 |
| 人机，玩家自己打出圣甲护身诀 | 说了自己的招：「圣甲护身诀命中」 | 说了剩余护盾 210，没说「获得 210 点」这几个字，但盾值在 | 当次返回，并立刻再数 321                 |
| 人机，电脑打出破风斩等       | 有：「中了破风斩」               | 没有伤害点数。血量和剩余护盾能反推，减伤和吸收不说      | 嵌在下一次工具返回里，不在空等里主动推送 |
| 联机，客人圣甲护身诀命中     | 调用方没听到招式名               | 当拍没听到。下一轮 `看血` 才出现「你护盾210」           | 晚一轮，且要再问                         |
| 联机，房主被打断             | 没有客人的招式名                 | 没有。只有「吟唱被打断。」                              | 当次返回，信息不完整                     |

信息完整度：人机能知道电脑用了哪一招，不能直接知道掉了多少、护盾吸了多少、身上有什么状态。联机连招式名都经常到不了该听的那一侧。

## 5. 优先补什么

下面四条是修之前的生产现象。代码状态见文首「修复状态」：本地已绿，线上要等部署后再验，不能当成生产已通过。

**P0（代码已修，线上待复验）**

1. 联机枢纽兜底「刚才没听清，请再说一次。」不能盖住已经写上的选角、准备、施法及认输。调用方要听到引擎原句：开战
   321、技能名、打断、胜负。本地：预算过后仍交回已完成的引擎句；快照里已有的命令用
   `replay` 交回原句。
2. 结算当拍必须让双方听见对方招式名，以及这一击对自己的血量或护盾变化。修之前被打断只有「吟唱被打断。」本地联机用例里，命中侧是「破风斩命中。你1000血。对手935血。」，被打断侧是「吟唱被打断。中了破风斩。你935血。对手1000血。」
3. 断线超过 10 秒要判负。修之前 `disconnectDeadline` 固定写成
   `null`。本地：断开满 10 秒，或换会话且空档超过 10
   秒，再开口得到「你输了。」10
   秒内回来得到「回来了。」加现状。同一会话里单纯停顿不判负。
4. 人机请求若慢于电脑出手，玩家的技能和「看血」会被电脑战况替换。本地：`看血`
   仍是状态句，电脑的「中了破风斩」留在随后的
   `wait_event`；已经开口再晚到的技能听到打断和这一击，而不是被静默换成电脑战况。

**P1**

1. 战况补上伤害点数、护盾吸收和状态名。剩余血量、剩余护盾不够用来确认「对我造成了什么」。
2. 电脑出手要推给正在等待的玩家，不要只在下一次开口时才嵌进去。空 `wait_event`
   不应只回句号，也不应把阶段标成 `LOBBY`。
3. 练习与对战都按标准技能名完全一致判定，或把近音纠偏写成明确规则。现在「破风站」会打出
   44 点。
4. 练习要把增益和复合效果说完，不要停在「已记下。」或只说第一段效果。
5. 复盘要有胜负、最终血量和最后三击，包括对手用过的招。
6. 电脑预备语音要进 `clips`，并编成 `linx_play`。现在数组是空的。
7. 进房当时就要让房主听到「对手来了。」不要等下一句准备才把「对手选了某角色」补上去。

**P2**

1. 练习不加木桩也可以打完技能反馈。若要听见「打在人身上怎样」，再加只报数值、不记胜负的木桩。
2. 单次 5–12 秒的边缘函数耗时，会顶满 3
   秒倒数。即便兜底句修好了，抢先手感仍然紧。
