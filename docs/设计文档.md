# 烈焰燎原 · 产品设计

语音咒语对战。双方可以同时念技能。谁先把技能完整念到服务器，谁的技能结算，并打断对方还没念完的技能。念得越准，直接伤害越高。血量先到
0 的一方落败。

| 终端     | Web（完整体验）；灵矽等智能陪伴硬件（拓展终端）                                    |
| 本文     | 市场、目标、商业、用户、功能范围和主流程                                           |
| 玩法细则 | [玩法设计](./gameplay-design.md)：角色、技能、施法、打断、完成度、胜负、服务器裁决 |
| 交互     | [交互设计](./交互设计.md)：主持词、灵矽上怎么说怎么听，以及一场的时序              |

## 1. 市场

两股变化正在相遇。语音识别和大模型让「说一句话」足够准、足够快，可以作为游戏操作。智能陪伴硬件把带角色声音的麦克风放进了家庭和孩子身边。语音游戏缺一个让人反复开口的玩法，陪伴硬件缺一件让人反复打开的内容。烈焰燎原站在两者的交汇处。

### 1.1 语音游戏：需求长期存在，玩法稀缺

用嘴玩的游戏一直有人玩：成语接龙、猜谜、绕口令、桌游里的喊牌。需求来自三类时刻：

| 时刻             | 为什么适合语音                           |
| ---------------- | ---------------------------------------- |
| 不看屏、不动手   | 睡前、做家务、亲子陪伴时，眼睛和手被占着 |
| 几个人同处一室   | 开口就能参与，不用传手机、不用分屏       |
| 发音本身是一门技 | 普通话、背诵、绕口令，人愿意练到更准     |

过去这类游戏停在问答和测验：一问一答，没有对抗，也没有成长。识别不稳时，判定无法让人信服，对战就立不住。

现在，实时语音识别可以把一句技能名转成文字，并给出 0–100
的完成度。服务器只接受当前角色的标准技能名，再按完成度结算直接伤害。大模型可以把局面说成连续的主持词，但不参与胜负计算。语音游戏可以具备成熟品类的三个条件：

1. 操作有深度：技能名越长，收益通常越高，也越容易在念完前被对方打断。完成度越高，直接伤害越高。
2. 结果可信：生命、护盾、状态和胜负由服务器按规则结算。主持只负责播报。
3. 能对人：两个人同时念技能。先完整到达服务器的技能生效，并打断对方还在念的技能。

同时具备这三点的语音游戏仍然很少，这是烈焰燎原进入的位置。

### 1.2 智能陪伴硬件：入口已经铺开，内容跟不上

大模型接入之后，AI
玩具、桌面陪伴机器人和带人设的音箱，从「回答问题」走向「陪着说话」。角色、性格和声音成为卖点，家长为陪伴和学习属性付费。设备的购买理由从「它能回答」变成「它在身边」。

这类设备面临同一个问题：新鲜感过去之后，开机次数下降。闲聊没有目标，问答没有结束；两个人同时在场时，设备仍然只会一对一聊天。

而一台无屏游戏主机需要的能力，这些设备已经具备：

| 游戏需要 | 陪伴硬件已有         |
| -------- | -------------------- |
| 输入     | 常开的麦克风         |
| 输出     | 喇叭和角色声音       |
| 身份     | 声纹，区分谁在说话   |
| 连接     | 联网，两台设备可互通 |

陪伴硬件下一阶段比拼的是留存，所需要的是有规则、有胜负、能多人一起玩的内容。

### 1.3 结合：语音对战成为陪伴硬件的常驻玩法

语音对战补上的，正是陪伴硬件缺的那部分：

| 陪伴硬件需要 | 烈焰燎原提供                                   |
| ------------ | ---------------------------------------------- |
| 反复被唤醒   | 一局有明确胜负，结束即可再开                   |
| 长期成长     | 技能完成度和角色技能组。越练越准，有新角色可练 |
| 多人在场     | 声纹把一台麦分成两个座位，两个人在一台设备上打 |
| 角色人设     | 角色声音担任主持，报开战、血量和胜负           |
| 远程连接     | 两台设备各开一端，四位房间号联机               |

游戏也从硬件得到入口：设备已经在家里、已经开机，玩家开口即可开局，不需要另装客户端，没有屏幕也能打完。

市场按两层展开。第一层是游戏本身：在 Web
上独立运营，积累玩家、角色和赛季，内容不绑定任何机型。第二层是硬件渠道：每接入一类具备麦克风和喇叭的陪伴设备，就多一个开局入口。灵矽是第一个接入的终端，接入方式是标准的工具调用接口，可复制到其他同类设备。

## 2. 目标

### 2.1 首先是一款独立游戏

烈焰燎原是一款完整的游戏应用。玩家不连接任何硬件，在 Web
上就能学习技能、与电脑对战、与其他玩家联机，并打完一整局。选角、完成度、生命、护盾、回合和胜负都由游戏自身定义和结算。离开灵矽，产品照样成立，体验照样完整。

### 2.2 灵矽是拓展终端

灵矽是游戏接入智能硬件的第一个渠道。这类设备天然适合语音对战：

| 设备能力 | 在对局里承担                                 |
| -------- | -------------------------------------------- |
| 麦克风   | 出招。开口开始施法，念完标准技能名即完成施法 |
| 喇叭     | 棋盘。主持报出局面                           |
| 声纹     | 座位。区分两位玩家                           |
| 角色声音 | 主持人                                       |

接入灵矽，规则、角色和技能与 Web 相同。灵矽带来两样 Web
没有的东西：一台设备上的两人对战，以及由角色声音连续主持的整局。无屏时说什么、听什么，见交互设计。

### 2.3 要达成的效果

| 对象     | 效果                                                           | 观察口径                       |
| -------- | -------------------------------------------------------------- | ------------------------------ |
| 玩家     | 一次打开内练会一个技能，听出完成度高低对伤害的差别，并打完一局 | 首局完成率；学习转入对战的比例 |
| 玩家     | 无屏时也知道谁领先、本回合谁的技能生效、双方还剩多少血         | 对局中途离开率                 |
| 游戏     | 只用 Web 即可完整体验；新角色一次发布进入全部玩法              | Web 独立留存；新角色练习次数   |
| 灵矽渠道 | 设备被反复唤醒；两个人一起打开同一台设备；两台设备远程对战     | 设备周对局数；同机双人开局占比 |

所有终端遵守同一条裁决：一方生命 ≤ 0、另一方 > 0，则生命大于 0
的一方胜。双方同时 ≤
0，且按效果顺序无法区分先后时，为平局。认输或主动离开则对方胜。断线先保留 10
秒，超时未重连视为离开。主持只播报结果。

## 3. 商业价值

一句话：免费打完一整局，付费买下一套要重新练的技能；硬件渠道为游戏带来不用安装的玩家，游戏为硬件带来反复唤醒的理由。

### 3.1 价值来源

| 价值         | 稀缺在哪                                                                   | 玩家用什么交换                           |
| ------------ | -------------------------------------------------------------------------- | ---------------------------------------- |
| 熟练度       | 同一技能的完成度决定伤害成色。短技能更容易先念完并打断对方，长技能收益更高 | 时间。重复念，换来更准的伤害和更稳的打断 |
| 角色技能组   | 新角色是另一套 7 个技能名，句子要重新练，打法也随之改变                    | 付费购买                                 |
| 可比较的结果 | 联机胜负可信，排名和观战才有内容可听                                       | 赛季                                     |

角色是一套打法，由必须亲口念出的技能组成。玩家买到的是新的句子，以及这些句子在对局里的职责：打断、伤害、治疗、护盾、增益、减益或限制对方下一回合行动。规则、完成度和胜负保持不变。新角色因此直接进入学习、对电脑、同机双人和联机，一次发布，全部玩法同时换技能。

赛季建立在可信的胜负上。一段时间内的排名给熟练度一个比较对象。观战沿用对局主持，听众听到的就是这一局的开战、回合和血量。赛季与观战不在首版范围，见第
9 节。

### 3.2 收入

| 来源       | 付费方   | 卖什么                                 | 成立条件                           |
| ---------- | -------- | -------------------------------------- | ---------------------------------- |
| 角色技能组 | 玩家     | 新角色及其 7 个技能，按季发布          | 新技能名要重新练；四种玩法同时可用 |
| 赛季与观战 | 玩家     | 赛季排名、观战                         | 联机胜负由规则结算，结果可信       |
| 渠道合作   | 硬件厂商 | 内容接入；把设备自有角色做成联名技能组 | 对局提升设备唤醒频次和多人使用时长 |

### 3.3 灵矽渠道的价值

同机双人随灵矽提供，作为设备的玩法，计入渠道价值，不单列收费。

| 一方 | 投入                         | 得到                                                       |
| ---- | ---------------------------- | ---------------------------------------------------------- |
| 游戏 | 规则、角色、技能、主持词     | 已在家中开机的入口；免安装的新玩家；可做成技能组的角色形象 |
| 灵矽 | 麦克风、喇叭、声纹、角色声音 | 一件能反复打开、两人能一起玩完的常驻内容                   |
| 玩家 | 开口                         | 身边这台设备变成游戏主机，朋友家人坐下就能对战             |

账号绑定后，进度跨终端互通：在灵矽上留下的练习记录、在 Web
上购买的角色，两边都能用。硬件拿到使用时长，游戏拿到玩家，两边的留存落在同一份进度上。

### 3.4 复购

复购分三层，一层推着下一层：

| 再来一次   | 玩家感到的差别                                                   | 商业上接住它                     |
| ---------- | ---------------------------------------------------------------- | -------------------------------- |
| 同一个技能 | 完成度不同，伤害不同；短技能用来打断，长技能用来打更高收益       | 免费时长；形成购买新角色的意愿   |
| 下一个角色 | 7 个新技能名要重新练，职责也换                                   | 角色付费                         |
| 下一个人   | 对电脑验证技能念得出去；对人由谁先念完决定这一回合；同机就在身边 | 联机、赛季，以及灵矽上的双人开局 |

### 3.5 成本与收费边界

| 项       | 说明                                                                                                                       |
| -------- | -------------------------------------------------------------------------------------------------------------------------- |
| 内容成本 | 一个角色是 7 个标准技能名、使用规则和效果配置。新角色复用全部回合规则，制作集中在设计和配音                                |
| 服务成本 | 匹配技能名、打断和结算由确定规则完成。大模型负责大厅里听懂指令，以及把服务器事件说成主持词。单局成本随语音轮次增长，可预估 |
| 渠道成本 | 按标准工具接口接入，新增一类设备复用同一套服务                                                                             |

| 保持免费                             | 原因                                                       |
| ------------------------------------ | ---------------------------------------------------------- |
| 首发四名角色、学习、对电脑、联机开房 | 玩家先打完一局，再判断下一个角色是否值得买                 |
| 完成度规则                           | 同一技能的伤害差别只来自念得准不准，付费买到的始终是新角色 |
| 胜负判定                             | 生命和回合裁决与购买无关                                   |

## 4. 用户与场景

| 用户                       | 场景                         | 使用方式                       |
| -------------------------- | ---------------------------- | ------------------------------ |
| 想把技能念准的人           | 单独练习某一个技能           | 学习。Web 或一台灵矽           |
| 想马上打一局的人           | 身边没有对手                 | 对电脑。Web 或一台灵矽         |
| 家里有陪伴设备的亲子、朋友 | 坐在一起，只有一台带麦的设备 | 灵矽同机双人。开局各录一句声纹 |
| 不在一处的两个人           | 各自有浏览器或设备           | 联机。四位房间号               |

Web 单机只有对电脑。Web
联机是玩家对玩家。灵矽单机包含对电脑和同机双人。灵矽联机是两台设备各一端。

## 6. 主流程

```text
进入
  → 学习 | 对电脑 | 同机双人 | 联机
学习
  → 选角色 → 看 7 个技能 → 念技能名 → 听到是否念对、完成度和效果 → 可转入对战
对战
  → 选角色（未选角不能准备完成）
  → 对电脑：玩家准备后开战。未指定对手角色时，对手是烈焰剑士
  → 同机双人：两人各录声纹，各自选角
  → 联机：开房或输入四位房间号，各自选角
  → 准备
  → 开战
  → 回合循环。Web、两台灵矽和同机都同时施法，先完整到达的技能结算并打断对方
  → 结算 → 复盘 → 再开一局
```

上一局的生命、护盾、技能次数和状态不带入下一局。再说「再来一局」时，沿用刚才的角色和对手，双方都确认后新建对局。要换角色就先说角色名。

同机双人只有一只喇叭，主持用座位甲、座位乙。两个人同时念。能同时认出就两句都送上。做不到时，先被识别出来的那一句参加抢先。Web
和两台灵矽各听自己的「你 /
对手」，同时念，先到的技能打断对方。灵矽用自己的转写。对方录音只在战况发出前已经拿到时播放，不拖住倒数。被打断的那一句不结算，下一回合两边仍可念。细节见交互设计。

## 7. 学习与对战要让玩家感觉到什么

学习的目的，是让玩家熟悉所选角色的 7
个技能名，并听清完成度如何改变直接伤害。练习不计胜负，不消耗技能次数。没买的后续角色不能练。可选木桩只把这一档数值念出来，不进正式战绩。

对战的手感是：

- 每个角色 7
  个技能。战前选定，本局锁定。首发四名角色默认可免费使用：烈焰剑士、圣光守卫、暗影术士、风行弓手。
- 双方同时念。先完整到达的合法技能结算，并打断对方还没念完的那一招。同机也同时念。先被识别出来的那一句参加抢先。
- 念得越准，直接伤害和持续伤害越高。治疗、护盾、增益、减益和控制不按完成度打折。
- 短技能用来抢先打断，长技能收益更高，也更可能被打断。
- 一方生命降到 0 且另一方仍存活，则存活方胜。双方同时降到 0
  且分不出先后，是平局。双方一直存活，就听完这句战况，等服务器倒数结束后再念下一招。
- 断线保留 10 秒。超时、投降或主动离开，对方胜。已经进入结算的技能先算完。

生命、护盾、技能表、伤害公式、打断和服务器状态，全部以玩法设计为准。本文不另写一套数值。

## 8. 账号与进度

未绑定也可以在当前终端打完一局。绑定之后，下列进度两端可用：

| 进度         | 两端互通                                     |
| ------------ | -------------------------------------------- |
| 已购角色     | 是。未购角色不能选、不能练                   |
| 练习记录     | 是。记录角色、技能名、完成度、时间。不含胜负 |
| 正式对局档案 | 是。只读，不回放成可继续的对局               |

首发四名角色默认已拥有，不需要购买。

## 9. 后续内容

在现有完成度、同时施法、打断和胜负之上可以增加：更多角色及其 7
个技能、对电脑的不同风格、练习准确率的长期记录、观战与赛季。这些不改变玩法设计里的技能结构和阶段顺序，也不改变交互设计里「战况只播已结算结果、咒语语音不参与裁决」的边界。

新的陪伴硬件按同一类工具接口接入，沿用全部规则、主持和内容。2 对 2
若要做，另立规则。

## 10. 验收

1. 不连接任何硬件，只用 Web 就能完成学习、对电脑和联机，并再开一局。
2. 新玩家能在一次使用中练会一个技能在不同完成度下的伤害差别，并打完一局对电脑。
3. 同一句话、同一完成度，在学习和对战中的结果一致。
4. 未选角色不能完成准备。
5. Web 可以学习、对电脑、联机。Web 没有同机双人入口。
6. 一台灵矽可以学习、对电脑、同机双人。同机双人的句子落到正确座位。认不出说话人时不记到另一边。
7. 两台灵矽可以开房对战。两边听到开战主持，以及各自视角的血量。
8. 绑定账号后，练习记录和已购角色在 Web 与灵矽都可用。首发四名角色默认可选。
9. 战报是连续主持。玩家能听清本回合谁的技能生效、双方还剩多少血。

技能是否打断、伤害怎么算、次数和状态怎么扣，按玩法设计的验收。灵矽口令和主持句，按交互设计的验收。
