## 0. 产品原则（四句）

1. **游戏是独立整体、自循环**：大厅 → 选角 → 学习/单机/联机 → 结算 → 再开。**Web
   可玩**。规则权威在游戏侧。
2. **灵矽是载体终端**：经云端 MCP 对接；单机（一台设备 vs 电脑 /
   同机双人+声纹）与联机（双设备）是**比赛主看点**。
3. **学习模式练咒**：熟悉卡牌咒语；发音完成度（完美/普通等）决定效果层次；对战共用同一套评级。
4. **多角色 × 多卡牌，战前选角**：选角锁定本局卡组。

```text
【核心】游戏引擎（学习 / 单机 / 联机 / 选角 / 评级）
    ├── Web：学习 · 单机(仅 vs 电脑) · 联机(玩家 vs 玩家)
    └── 灵矽 MCP：单机(vs电脑 | 同机双人+声纹) · 联机(双设备)
```

## 1. 商业价值 & 产品设计（50%）

### 1.1 要解决什么问题

| 痛点                     | 说明                                                                      |
| ------------------------ | ------------------------------------------------------------------------- |
| 语音娱乐缺「可输赢」结构 | 多数语音助手停在问答/播歌，缺少公平、可复盘的对战闭环                     |
| 卡牌对战门槛高           | 传统卡牌靠点选与记忆；「口嗨念咒」降低操作门槛，但需要练咒与反馈          |
| 硬件演示难成产品         | 纯 Demo 难延续；需要**可 Web 自玩的游戏本体**，硬件是增强终端而非唯一入口 |
| 同机双人难区分说话人     | 一台设备两人玩时，必须靠声纹等能力分座位，否则无法公平结算                |

### 1.2 目标用户与场景

| 用户                | 场景                                     | 终端                     |
| ------------------- | ---------------------------------------- | ------------------------ |
| 轻度玩家 / 朋友聚会 | 沙发上同机对骂念咒、看谁先把对方血量打空 | 灵矽单机同机双人（声纹） |
| 个人练习 / 通勤碎片 | 学咒、打电脑、熟悉角色                   | Web 或单台灵矽           |
| 远程好友            | 各自设备开房联机                         | Web↔Web 或 灵矽↔灵矽     |
| 展会 / 比赛评委     | 两分钟内听懂：念咒→评级→开战→血量→胜负   | 双设备联机演示           |

### 1.3 价值主张

**一句话**：把「念准咒语」做成可训练、可分层生效的核心操作，用独立游戏规则保证公平，用灵矽把客厅变成战场。

| 主张               | 产品对应                              |
| ------------------ | ------------------------------------- |
| 念得越好，打得越疼 | 完美 / 普通 / 未完成 → 不同效果层次   |
| 先学会再对打       | 学习模式专项练卡牌咒语                |
| 一个游戏，多端入口 | Web 完整自循环；灵矽是语音沉浸终端    |
| 公平可复盘         | 服务端裁判；血量到 0 才分胜负；可复盘 |

**不做**：抄袭既有商业「口嗨巫师」类作品的名称与卡组；不做「只有硬件才能玩」的封闭
Demo。

### 1.4 模式矩阵（产品能力边界）

| 模式     | 子类型               | Web | 灵矽                   | 商业含义                           |
| -------- | -------------------- | --- | ---------------------- | ---------------------------------- |
| **学习** | 练咒 + 评级反馈      | ✅  | ✅ 单设备              | 降低上手成本，拉长留存前的「练功」 |
| **单机** | 玩家 vs 电脑         | ✅  | ✅ 一台设备            | Web 获客与日常；设备也能独处玩     |
| **单机** | 玩家 vs 玩家（同机） | ❌  | ✅ 一台设备 + **声纹** | 聚会神器；硬件差异化卖点           |
| **联机** | 玩家 vs 玩家         | ✅  | ✅ 两台设备            | 社交传播；比赛主秀                 |

- Web **单机只打电脑**；Web **联机支持真人**。
- 灵矽 **联机** + **同机双人（声纹）** 构成硬件独特体验，难以被纯网页替代。

### 1.5 核心体验循环（自循环）

```text
进入 → 学习 | 单机 | 联机
  学习：选角色 → 练卡牌咒语与评级 → 转对战
  单机：vs电脑（Web/灵矽）| 同机双人+声纹（仅灵矽）
  联机：选角 → 开房/进房（Web 或双灵矽）
→ 准备 → 主持「三。二。一。开战」→ 多回合念咒
→ 血量≤0 分胜负 / 超时平局 → 复盘 → 再开
```

**战前必选角色**：未选角不能准备完成；选角锁定本局卡组。

### 1.6 角色、卡牌与差异化

- **多角色**：定位差异（爆发 / 控制 / 防御等，名单可迭代）。
- **每角色多卡牌**：卡牌 = 可念出的咒语（瞬发、吟唱、护盾、禁言等）。
- **信息差与克制**：卡组不同，但匹配/评级引擎统一。
- **内容可运营**：新角色、新咒、季节卡组，不改架构即可扩展。

现网 demo
用一套共用咒作「默认卡组」原型（火矢、水幕、寒霜止步、烈焰燎原、九天神火焚尽八荒），目标形态拆入多角色并扩展专属牌。

### 1.7 学习曲线与完成度设计

学习模式**主用途**：熟悉与练习卡牌咒语。

| 评级       | 玩家感知            | 效果层次                         |
| ---------- | ------------------- | -------------------------------- |
| **完美**   | 念准了              | 完整效果（满额；「命中」）       |
| **普通**   | 差不多              | 削弱效果（如约七成伤；「擦中」） |
| **未完成** | 念飞了 / 一次念两张 | 不生效                           |

学习中即时报评级并演示层次差异，再带进对战——**同一套规则**，避免「练习一套、实战另一套」。

### 1.8 关键用户旅程（故事板）

**旅程 A · Web 获客**：打开网页 → 学习念「烈焰燎原」听到完美/普通差异 →
单机打电脑赢一局 → 开房约朋友联机。

**旅程 B · 客厅同机（比赛可演）**：一台灵矽 → 两人录入声纹 → 各选角色 →
三二一开战 → 交替念咒 → 血量播报 → 分出胜负。

**旅程 C · 双设备联机（比赛主秀）**：两台灵矽开房 → 各自选角准备 →
两边喇叭同步主持与回合血量 → KO 或认输。

### 1.9 体验原则（产品设计质量）

| 原则       | 要求                                                       |
| ---------- | ---------------------------------------------------------- |
| 连贯主持   | 三二一开战一口气念完；战报一句一拍；禁止「为您播放」割裂感 |
| 规则直觉   | 血量到 0 才输；超时平局；不搞「时间到比谁血多」的误解      |
| 反馈即时   | 念完立刻知道完美/普通/没成                                 |
| 失败可恢复 | 工具超时静默再挂起；对局不因一次取消而烂尾                 |
| 终端诚实   | Web 不承诺同机声纹双人；灵矽不承诺替代 Web 的全部 UI       |

### 1.10 商业与扩展路径（简述）

| 阶段 | 重点                                          |
| ---- | --------------------------------------------- |
| 现在 | 规则闭环 + 灵矽 MCP 演示 + Web 可玩雏形       |
| 近   | 多角色卡组、学习模式数据（完美率）、Bot 难度  |
| 中   | 内容运营、赛季、观战/录像；硬件捆绑或渠道合作 |
| 远   | 更多语音终端适配（同一游戏核心，多 Adapter）  |

收入与增长可讨论方向（非承诺）：内容
DLC、硬件套装、活动赛事——前提是**游戏本体可独立玩**，硬件卖体验升级。

### 1.11 成功指标（产品）

| 类型 | 示例                                          |
| ---- | --------------------------------------------- |
| 体验 | 新用户 10 分钟内完成：学一张咒 + 打完一局电脑 |
| 质量 | 联机局「误判归属 / 卡死无战报」率             |
| 学习 | 各卡完美率随练习次数上升                      |
| 演示 | 评委 3 分钟内理解「念咒=出牌、评级=强度」     |

## 2. 架构设计（20%）

### 2.1 架构原则

1. **游戏核心与终端适配分离**：规则、房间、结算只在一处；Web / 灵矽是 Adapter。
2. **服务端权威**：客户端与 LLM **不能**私自改血量；模型只选工具、念返回文本。
3. **一种状态机，多路 I/O**：学习 / 单机 / 联机共用对战引擎。
4. **可测试、可仿真**：逻辑与 MCP 传输分层；双假设备可跑通联机。

### 2.2 逻辑架构

```text
┌─────────────────────────────────────────────────────────┐
│ 表现 / 终端                                               │
│  Web Client          灵矽设备 / 网页体验（Agent+TTS/ASR）   │
└───────────────┬───────────────────────┬─────────────────┘
                │ HTTP/WS API           │ MCP (Streamable/SSE)
                ▼                       ▼
┌───────────────────────┐   ┌─────────────────────────────┐
│ Web Gateway（规划）     │   │ MCP Adapter（已有）           │
│ 会话、推送、房间码       │   │ 工具映射、信箱、hold、声纹座位  │
└───────────┬───────────┘   └─────────────┬───────────────┘
            └───────────────┬─────────────┘
                            ▼
            ┌───────────────────────────────┐
            │ 游戏核心 Domain                 │
            │ 选角 · 卡组 · 匹配评级 · 吟唱    │
            │ 打断 · 回合 · 胜负 · 学习反馈   │
            └───────────────┬───────────────┘
                            ▼
            ┌───────────────────────────────┐
            │ 持久化：Postgres / MemoryStore  │
            │ 房间状态 · outbox · hold        │
            └───────────────────────────────┘
```

### 2.3 领域边界

| 模块         | 职责                                     | 非职责                       |
| ------------ | ---------------------------------------- | ---------------------------- |
| 游戏核心     | 规则、HP/法力、channel、评级、胜负       | ASR、TTS、声纹算法本身       |
| MCP Adapter  | 工具 schema、设备身份、信箱、wait 自循环 | 编造战报、替模型「聪明发挥」 |
| Web Gateway  | UI 会话、实时推送                        | 另一套胜负规则               |
| 平台（灵矽） | ASR/TTS/声纹/Agent                       | 游戏数值                     |

### 2.4 对战状态机（摘要）

```text
lobby →（选角/模式）→ ready → battle → ended →（复盘）→ lobby
                ↘ learn（可随时回 lobby）
```

- `battle`：tick 结算到期吟唱、检查 KO / 超时。
- 联机：按 `deviceId` / 会话分座位。
- 同机双人：按**声纹 → 座位**分归属；仍是同一 `battle` 状态机。

### 2.5 身份与座位

| 场景         | 身份键                                       |
| ------------ | -------------------------------------------- |
| 联机双设备   | `X-Linx-Device-Id`（等），禁止模型自报       |
| Web 联机     | 会话 / 用户令牌（规划）                      |
| 同机双人     | 设备内座位 A/B + 声纹 ID                     |
| 单机 vs 电脑 | 玩家座位 + Bot 座位（服务端驱动 Bot `cast`） |

### 2.6 灵矽适配要点（已落地方向）

| 点          | 设计                                                |
| ----------- | --------------------------------------------------- |
| 传输        | Streamable HTTP 为主；兼容 SSE                      |
| 信箱        | 战报按设备入队；`wait_event` / 可兑现 `ready` 取走  |
| Hold        | Streamable 等待时 hold，防 SSE 泵抢结果             |
| 空等        | ~18s 交还「。」，避开平台 ~26s 取消                 |
| 播报        | 主叙事纯文本；避免 `linx_play` 标题触发「为您播放」 |
| change_role | 不与开战台词同拍；结算复盘拆拍                      |

### 2.7 部署视图

| 环境 | 组件                                                                    |
| ---- | ----------------------------------------------------------------------- |
| 线上 | Supabase Edge `mcp` + Postgres（房间 / peek / ack / hold）              |
| 本地 | `MemoryStore` + `deno task dev` / `sim`                                 |
| 工程 | `src/game/logic.ts` 核心；`src/mcp/*` 适配；`scripts/sim_match.ts` 仿真 |

### 2.8 关键质量属性

| 属性   | 手段                                       |
| ------ | ------------------------------------------ |
| 公平   | 权威状态机；同时窗 300ms；长咒互不打断     |
| 韧性   | 断线后状态在库；模型重挂 `wait_event` 续局 |
| 可演进 | 新终端 = 新 Adapter；核心不改              |
| 可观测 | 房间日志、工具结果文本可复盘               |

## 3. AI 价值呈现（15%）

> 评分关注：**产品里的 AI 元素、AI 味道**。烈焰燎原把 AI
> 能力做成**玩法部件**，而不是聊天皮。

### 3.1 AI 能力地图

| AI 能力                  | 产品内角色                  | 玩家可感知价值                       |
| ------------------------ | --------------------------- | ------------------------------------ |
| **ASR**                  | 把念咒变成出牌输入          | 免手柄；「喊出来才算」               |
| **发音完成度匹配**       | 完美/普通/未完成 → 效果层次 | 技术藏在乐趣里：念得好有奖励         |
| **声纹识别**             | 同机双人分座位              | 一台设备两人公平对战（硬件+AI 卖点） |
| **LLM Agent**            | 选 MCP 工具 + 原样主持播报  | 无屏设备也能走完选角/开房/开战       |
| **TTS**                  | 战场主持、血量、胜负        | 连续「解说感」，非菜单音效           |
| **Bot（可含策略/生成）** | 单机对手                    | 随时可玩；学习后的试炼               |

### 3.2 「AI 味道」叙事（评委可读）

1. **输入即魔法**：没有点选卡牌为主路径，**声音是技能释放**。
2. **质量即数值**：AI
   不是判「对错」一刀切，而是**完成度曲线**驱动伤害/控制层次。
3. **身份即座位**：声纹让「谁在施法」成为规则的一部分。
4. **Agent 即司仪**：模型不当裁判改血，只当**会调用工具的主持人**——AI
   有边界才有可信对战。

### 3.3 与「普通语音助手」的差异

| 普通助手           | 烈焰燎原                 |
| ------------------ | ------------------------ |
| 一问一答，无胜负   | 多回合状态、HP、KO       |
| 模型自由发挥易幻觉 | 工具返回文本约束播报     |
| 单用户会话         | 双座位、双设备、声纹同机 |
| AI 在对话框里      | AI 在**战场规则**里      |

### 3.4 演示时建议突出的 30 秒

「请听：玩家念寒霜止步 → 系统报完美/普通 → 三二一开战 → 两边血量 → 有人到 0
落败。」\
若有同机双人：加一句「同一台设备，声纹认出是谁在念。」

## 4. AI 工程效率（15%）

> 评分关注：**AI 使用姿势 / 效率**——如何用对模型、少踩坑、可回归。

### 4.1 分工姿势（核心效率原则）

| 职责                       | 承担者                                   | 原因                               |
| -------------------------- | ---------------------------------------- | ---------------------------------- |
| 胜负、伤害、CD、打断       | **确定性规则引擎**                       | 可测、可复盘、防幻觉改分           |
| 意图路由（开房/念咒/看血） | **LLM + 工具**                           | 口语多变，适合模型                 |
| 念咒是否匹配卡牌           | **拼音/音节算法**（非 LLM 自由发挥）     | 低延迟、稳定、可单测               |
| 播报措辞                   | **服务端生成固定文本**，模型**原样朗读** | 避免「为您播放」「恭喜获胜」类戏精 |
| 声纹                       | **平台能力** → 座位 ID 进核心            | 模型不猜「这是谁」                 |

**姿势总结**：LLM 做「司仪与路由器」，不做「黑箱裁判」。

### 4.2 MCP 作为稳定契约

- 工具面清晰：`create_room` / `join_room` / `ready` / `cast` / `wait_event` / …
- 身份走 Header，不进模型参数。
- 长等待用 `wait_event` + 信箱，适配平台取消窗口（提前交还「。」再挂）。
- 控制台角色介绍与工具描述双约束，减少跑偏。

### 4.3 自循环与人肉值守

| 问题                    | 工程对策                                 |
| ----------------------- | ---------------------------------------- |
| 平台取消挂起调用        | HOLD_MS 内交还；提示词要求静默再调       |
| 开战被 change_role 吞掉 | 拆拍；开战纯文本                         |
| 「为您播放」割裂        | 主叙事不用 linx_play title               |
| 工具未进当次注册表      | 文档要求挂断重拨；不假装服务端能修平台表 |

目标：对局**自己转起来**，不靠人在聊天里手动救场。

### 4.4 质量与效率工具链

| 手段                 | 作用                     |
| -------------------- | ------------------------ |
| `deno test` 规则单测 | 评级、打断、KO、超时平局 |
| `sim_match` 双端仿真 | 无真机时回归 MCP 联机    |
| 提示词版本化         | LOBBY / 控制台粘贴稿一致 |
| 日志与房间 log       | 复盘「为什么这局这样判」 |

### 4.5 开发效率叙事（AI 辅助研发，若需对外说）

- 规则与适配分层，改玩法不拆传输。
- 仿真优先于真机联调，缩短设备侧迭代。
- 文档与提示词同源约束，减少「模型乱说话」返工。

## 5. 游戏规则细则

### 5.1 资源与常量

| 项                         | 值              |
| -------------------------- | --------------- |
| 生命                       | 30              |
| 开局法力 / 上限 / 回复     | 4 / 10 / 1 每秒 |
| 对局时长                   | 10 分钟         |
| 同时生效窗                 | 300ms           |
| 念偏 / 冷却失败 / 打断禁言 | 1.5s / 1s / 2s  |

### 5.2 胜负

| 条件                 | 结果                   |
| -------------------- | ---------------------- |
| 一方 HP≤0，另一方 >0 | 后者胜                 |
| 双方同时 ≤0          | 平局                   |
| 时间到               | **平局**（不比剩余血） |
| 认输 / 离开          | 对手胜                 |

### 5.3 主持与回合

- 开战：`三。二。一。开战。双方各30血。血量先到0的一方落败。开始念咒。`
- 效果结算回合 +1；战报示例：`第1回合。火矢命中。你30血。对手26血。`

### 5.4 匹配引擎（与学习共用）

1. 去非中文 → 无声调音节；去语气填充。
2. 完美 / 普通（四字≤1 错、八字≤2 错等；两字咒无普通档）。
3. 一句两咒 → 「一次一道。」
4. 普通档效果削弱（如伤害 ×0.7）。

### 5.5 吟唱与打断

| 情况       | 行为                                   |
| ---------- | -------------------------------------- |
| 长咒       | 扣费起 CD，进入吟唱                    |
| 瞬发打断   | 距结算 >300ms 可打断；不退还被断方法力 |
| 同时窗     | ≤300ms 不打断，双边结算                |
| 长咒对长咒 | 互不打断                               |
| 护盾       | 吸收一次伤害后清除                     |

### 5.6 原型咒语表（默认卡组）

| 咒语             | 法力 | 吟唱 | 冷却 | 效果              |
| ---------------- | ---- | ---- | ---- | ----------------- |

| 水幕             | 3    | 瞬发 | 8s   | 6s 挡一次，最多 8 |
| 寒霜止步         | 4    | 4.5s | 8s   | 3 伤 + 禁言 3s    |

| 九天神火焚尽八荒 | 9    | 8s   | 无   | 25 伤             |

### 5.7 MCP 工具映射（灵矽）
